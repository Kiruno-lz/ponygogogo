# 玩法设计

## 1. 产品范围

核心体验是“跟随自己的马横向竞速，用三次选牌和节奏点击把名次往前拱”。目标是最快到达终点。

每场固定五匹马，玩家可任意选择其中一只作为自己控制，其余四匹为电脑马。下注金额是难度的唯一来源：金额越高，电脑马越可能跑得凶。当前目标是先在浏览器内用本地 mock 跑通核心玩法的最小 Demo；所有比赛时逻辑在浏览器运行，未来接链后再由合约负责资金与记录；社交从结算海报分享开始。

**设计主线是多巴胺反馈，不是收益模型。** 下注、抽卡、点“快跑”、结算卡片展示这四个环节的存在理由，是给一场只有几十秒的赛马铺出反馈节奏：下注制造赛前紧张，抽卡制造中段的决策高峰，快跑给手上持续的动作，结算卡片给终局的确认与炫耀。爽感与平衡冲突时先保爽感——平衡是上线后持续调参的动态过程，不是 demo 阶段要求解的问题。

**比赛结果不在开局确定。** seed 固定的只是发到玩家手里的牌，电脑马的位置由浏览器逐步实时算出，名次在冲线那一刻才产生。开局即已写好结局的比赛没有游戏性，这条优先于任何可验证性诉求。

本作是单人游戏，不存在玩家之间的对抗：电脑马不下注、不领取任何 MON，只负责提供一场有张力的追逐。社交与流通性来自卡牌与结算海报的分享，而非玩家对抗。

画面采用二维横向赛道和马匹动画，可用分层背景形成纵深。赛道数等于马匹数，每匹马占一行；行与行之间没有碰撞，也没有连续变道动画——唯一改变站位的是【交换】类卡牌的瞬时置换（见第 6 节）。摄像机仅沿横轴跟随玩家，纵轴和缩放固定；对手可以离开画面。开局按固定五条赛道计算布局，确保玩家、赛道和操作区可见；方向箭头及名次 HUD 表示画外对手。

## 2. 开始界面与比赛流程

首页包含开始游戏、卡牌图鉴、游戏设置和中英文切换。设置仅包含音量等表现设置，不提供独立难度或马数选择。

首页未登录时并排显示注册与登录两个入口，各走一条 Mera 通行密钥路径：注册先弹取名窗口（默认 `ponygogogo`，只是认证器列表里的标签），确认后才建通行密钥并自动领一次测试币；登录唤起通行密钥回到同一个地址，有多把时由系统自己列出来让玩家挑。登录后木牌显示地址摘要与链上 MON 余额，退出登录就在木牌上；点开木牌是钱包面板——完整地址、网络、链上余额与游戏余额、重新领币、导出助记词。下注允许为 0 MON；0 MON 使用同一比赛流程和最低难度档位，总返还为零。完整链版本中 0 下注仍需支付 gas。

完整链版本整场比赛只有两笔交易：入场交易与结算交易。当前通过同名 `ChainPort` mock 保留这条生命周期，还没有合约可调；下注扣的是游戏余额，不动钱包里的真实 MON，两个数字在界面上分开列示。

1. 进入赛道，五匹马在起跑线前 idle 动作；玩家挑选其中一匹作为自己的马。
2. 输入下注额，展示该金额对应的难度档位、名次返还和费用。
3. Demo 调用 `ChainPort.enterRace` mock，发起passkey签名模拟交易；完整链版本再通过钱包提交入场交易。两者都在这一阶段确定下注档位、规则版本和本场 seed。
4. Demo 从 mock 返回的 seed 生成整副牌堆与四匹电脑马的性格参数；完整链版本从合约读回同一 seed。浏览器显示固定 3 秒起跑倒计时，不额外插入等待。
5. 浏览器执行竞速、电脑马追赶、快跑、体力和抽卡，比赛过程中不逐次发交易。
6. 玩家冲线，名次在该瞬间确定；浏览器跑完身后马匹的尾场并生成完整回放记录。
7. Demo 调用 `ChainPort.settleRace` mock，完整链版本再提交结算交易；两者接收浏览器算出的名次与记录。完成 tick、至多三次选牌与刷新位置一并作为战绩数据保存，合约不解析。完整链版本对名次只做 1–5 的范围检查，目的是防止赔付表数组越界，不是合理性判断；随后按名次查赔付表发放返还，不复算比赛过程。结算卡牌更新 mock 状态或交易状态和返还。
8. 分享海报或开始新的比赛。

**赛道是站位，不是身份。** 马由 `horseId` 标识，`horseId` 与赛道不绑定；`laneIndex` 只服务于相邻交换和渲染排布，不参与速度、里程、名次或同 tick 兜底排序。

**选马不改变难度。** seed 派生的是四组电脑马性格参数，玩家选走一匹后，这四组按剩余 `horseId` 升序依次分配（见第 7 节）。因此无论选哪匹，本场遇到的性格参数集合完全相同——难度的唯一来源仍然是下注金额。选马是代入感与视觉偏好，不是一个需要计算的决策。

比赛是一次性的，不提供中途存档或恢复。主动退出、刷新或关页视为弃赛，下注不退。弃赛就是不提交结算交易：没有弃赛状态，没有结算期限，没有退款，也没有链上过期清理；下注留在 Vault，下次比赛重新走一遍入场流程即可。资金定义见[链上规则](chain-and-economy.md)。单纯网络短暂中断不打断本地模拟；比赛完成后的交易重试不属于恢复比赛。

当前版本不设计任何防作弊机制。名次以浏览器的运行结果为准，玩家理论上可以跳过比赛直接提交第一名，合约不拦——这是测试网 demo 的明确取舍，防作弊被判定为反游戏性而延后，信任边界与将来怎么加验证见[无服务端方案探索](_reaserch/serverless.md)。

建议原型在页面隐藏时终止当前比赛，避免后台计时差异；明确向玩家说明该规则。链上无法识别关页事件，此处是产品行为而非链上浏览器检测能力。

## 3. 赛道、里程与名次

赛道长度为 L，终点在 L。**检查点不是赛道上的位置，是每匹马自己跑过的里程。** 每匹马维护两个独立的量：

| 量 | 定义 | 用途 |
| --- | --- | --- |
| `pos` | 当前在赛道上的位置 | 冲线判定、名次、镜头、身位差 |
| `dist` | 自身位移的累计，每 tick 加上本 tick 自身速度产生的位移 | 检查点抽卡 |

`dist` 跨过 0.25L、0.50L、0.75L 各触发一次抽卡，一场最多三次，同一档不重复触发。**位置跳变不产生里程**——【交换】把马挪到别处，`pos` 变了而 `dist` 不变。

两个量分开带来三个直接结果，都是有意的：

- **跑满 100% 里程不等于冲线**：被换到后面的马可能跑够了整条赛道的距离仍未到终点。
- **没跑满 100% 里程也可以冲线**：被换到前面的马直接过线，`pos ≥ L` 即完成。
- **提前冲线的马可能拿不满三次抽卡**：里程不够就是不够，这是用抽卡机会换捷径的代价，不做补发。

这套口径同时消掉了传送类卡牌的全部边界问题：来回交换刷不出第四次抽卡，被换到后面也不会重复触发已消费的档位。里程只吃自身速度，不吃任何跳变。

电脑马不打开人类选牌面板。每匹电脑马拥有一副由 `H(seed, "cpudeck", horseId)` 从可对电脑马生效的卡牌子集无放回派生的 3 张私有牌堆，在自己的里程档按顺序自动取牌并立即生效；不刷新、不等待、不做三选一。玩家的牌堆只由 seed 的发牌派生决定，与电脑马当场抽了什么完全无关。里程跨越使用前后状态检测，不能依赖动画或像素位置。

`laneIndex` 是规则状态，不是 `horseId`：它表示马当前所在的上下赛道位置，开局为 `0..4` 的固定排列，只能由【交换】修改。渲染层按 `laneIndex` 排列马匹；任何名次、里程、速度或同 tick 兜底排序都不得读取它。这样【交换】可以明确作用于画面上相邻的未冲线马，同时不把赛道位置误当成马的身份。

五匹马的位置都由同一套纯规则模块逐步推进，没有任何一匹马的成绩是预先写好的。名次是位置的副产品：谁先跨过 L 谁在前。**玩家冲线的瞬间，玩家自己的名次即已确定**——已冲线的马都赢了他，未冲线的马都不可能再排到他前面。尾场只决定玩家身后电脑马彼此的先后，可以快放，不阻塞结算面板。

玩家冲线后封存输入，Buff 不影响已完成马匹。同时电脑马关闭追赶项、按各自基础速度自由跑完剩余距离（见第 7 节）；否则玩家位置外推会让全部电脑马贴住速度上限，尾场退化成一条直线。

同一 tick 冲线时，比较跨线瞬间的连续位置（越过 L 的量），大者在前；仍相同则按 `horseId` 升序。不用赛道序，因为赛道只是画在第几行，改一次布局就会改掉名次。这里不需要额外的随机次序：位置是连续量，同值属于极端边界而非常态。

## 4. 检查点抽卡

玩家里程跨过 0.25L、0.50L、0.75L 的瞬间，展示三张不同 cardId 的牌，最多选一张，实际选择 0–3 张。超时用显式 `null` 记录，不能伪装成选了默认牌。

**发牌是一副 14 张的有序牌堆加一个游标，不是三次独立抽取。** seed 派生出 `deck[0..13]`，十四张互不重复；游标 `cursor` 从 0 开始，每个检查点从游标处连取三张展示，取完游标前进 3，放弃选择游标也前进 3。正常打完一场消耗 9 张。余下 5 张是**刷新的预算**，其中对于高品质刷新，独立维护另一个反向的游标，从最后一张牌开始计数。

**这副牌堆是整场比赛里唯一由 seed 固定的东西。** seed 存在的唯一理由，是让发牌可被事后验证为随机：任何人从链上读出本场 seed，按公开派生式

```
deck[12], deck[13] ← 从「强效果」子集中无放回取 2 张      // 保底，见下
deck[0..11]        ← 从剩余全部卡中无放回取 12 张
全部取牌用 H(seed, "card", 位置) 定序，位置按上面两步的顺序编号
```

**抽取顺序是派生式的一部分。** 无放回意味着第 k 张取决于前 k−1 张抽走了谁，复算方必须按同一顺序走完十四次才能得到同一副牌；换顺序就是换了发牌规则，要跟着升 `rulesVersion`。

卡池下限由此直接确定，不需要按品质分档论证：**总卡池 ≥ 14 张，其中「强效果」子集 ≥ 2 张。** 先抽保底两张再抽前十二张，前十二张因此仍可能出现强效果卡，牌堆不会被保底机制抽成两段。

重算出整副 14 张牌堆，再按记录里的刷新位置推算游标，与玩家当时看到的候选逐张比对，即可确认前端没有挑牌。**seed 不决定比赛结果，只决定发到手里的是哪几张牌。** 电脑马的性格参数同样从 seed 派生（见第 7 节），那只为让同一场里的对手性格稳定可复现；性格决定它们怎么跑，不决定它们几时到终点——追赶逻辑每步实时读玩家位置。

**刷新一次只换一张，不是重开三张。** 某些卡的效果是给后续检查点一次刷新机会：玩家点掉展示中的某一张，它被 `deck[cursor]` 顶替，游标前进 1，另外两张不动。顺延是全局的——第一个检查点若刷过一次，第三个检查点看到的就整体后移一位。

举例：无刷新时三次检查点分别看第 1–3、4–6、7–9 张。若在第二个检查点刷新一次，那一张换成第 7 张，第三个检查点就变成看第 8–10 张。

**最后两张必定是强效果卡**，这是刷新的保底：刷得越多，游标越靠近牌堆末尾，摸到保底强卡的可能越大。刷新因此不是无风险的重摇，而是一个「越往后越好」的爬升。这条激励结构是刷新机制存在的理由，调数值时不要把它调没了。

- 选牌时整场比赛降到 0.1 倍模拟速度，所有马、体力变化及 Buff 持续时间同步慢放。
- 选择时限为现实时间 20 秒，不被慢放。最后 5 秒显示显著数字倒计时，并提供音效；静音时仍有视觉提示。
- 选定后即时生效，关闭面板，恢复正常速度；20 秒到期视为放弃，恢复比赛。
- “快跑”按钮在选牌时隐藏，键盘及触控输入同样禁用。
- 卡牌没有目标选择操作：作用于自身的卡直接生效，作用于其他马的卡（炸弹、交换、重力井）按各自的固定规则选目标。候选卡直接显示效果、生效条件与对自身的代价。
- 电脑马在自身检查点从私有牌堆按顺序自动取牌并立即生效，不额外慢放；玩家面板开启期间电脑马也遵守全场 0.1 倍速。

同一时刻到期和选择竞争，以浏览器单调计时为准：`eventElapsedMs < deadlineMs` 才接受。边界时先处理超时，再处理输入；时间与事件顺序写入回放记录。

建议默认通过速度上限保证一次 20 秒慢放最多前进 2 秒模拟距离的里程，不会越过下一个里程档或终点。规则校验要求最短里程档通过时间严格大于 2 秒。传送类卡牌不需要额外规则：里程只累计自身位移，跳变既不给里程也不扣里程（见第 3 节）。

## 5. 快跑与体力

“快跑”始终出现在竞速 HUD，抽卡时和冲线后隐藏。桌面端固定快捷键为 `Space`，移动端为按钮触控；一次按下或一次点击只产生一个输入意图，按住和系统自动重复不产生连续点击。页面失去可见性时立即终止比赛并回到首页，不在后台继续模拟。

快跑是**次要输入**：它提供持续的节奏反馈，但不负责表达卡牌构筑。规则使用固定 50Hz tick 与定点整数；以下是能让 D1 直接开工的基础单位和初始常量，不是平衡结论，后续只能在实现与回归中调整：

| 量 | Demo 初始值 | 说明 |
| --- | ---: | --- |
| `simHz` | 50 | 1 tick = 20ms 模拟时间 |
| 距离单位 | `1/1000` 条赛道 | `L = 100000`，终点为 `pos >= L` |
| 玩家 `vLow` / `vHigh` | 24 / 40 | 每 tick 的距离单位 |
| 玩家 `aMax` / `aIdle` | 1 / -1 | `v` 每 tick 的最大增减量 |
| `vHardMax` | 80 | 任何外部场最终都必须钳在此值 |
| 体力 `max` | 1000 | 初始体力为满值 |
| 体力消耗 | `floor(2 × f̂)` / tick | 只在有效快跑节奏产生时消耗 |
| 体力恢复 | 1 / tick | 无有效快跑节奏时恢复 |
| 力竭解除 | `stamina >= 300` | 进入力竭后形成回滞 |

玩家速度不是“点击直接加速”，而是按当前状态计算加速度后积分：

```
f̂ = clamp(1 - abs(intervalMs - 500) / 500, 0, 1)
a  = aIdle + f̂ × (aMax - aIdle)
v  = clamp(v + a × 1 tick, vLow, vHigh)
pos += v
dist += v
```

首个点击只建立节奏，不产生 `f̂`；小于 100ms 的点击被拒绝；抽卡开始清空节奏历史，抽卡结束后的第一次点击重新建立节奏。`f̂` 不进入速度乘区，卡牌只改变速度带或其他明确声明的目标量。被 `Ability` 占用期间 `f̂` 固定为 0.5，不做实时判定。

体力降到 0 时挂载系统自持的【力竭】效果，速度带压到 `vLow` 且 `Space`/按钮锁定；恢复到 30% 才解除。死亡归零的是当前速度，不是速度带，并临时解除 `vLow` 直到速度爬回去；恢复加速度至少为 `aMax / 2`，保证力竭时也能结束比赛。

HUD 必须同时显示体力条、当前节奏提示和“力竭/恢复”状态；命中、过快、过慢使用三个不同音效，静音时保留颜色与文字提示。

## 6. 卡牌构筑

三次“3 选 1 或放弃”是玩家表达能力的主要途径，也是玩家成绩范围的主要决定因素：同一场里，最优构筑与不选牌的完成时间差距应当明显大于节奏操作带来的差距。

卡牌数据至少包含品质 `quality`、`cardId`、中英文名称与描述、图标、生效条件、效果参数、持续时间和叠加策略。规则表属于版本化比赛配置，正在进行的比赛不得被热更新改变。

构筑的深度不在候选组合数（不刷新时只有 3³ = 27 种），而在**时机与叠加顺序**：

- 一副牌堆内不重复出现同 cardId 的卡牌，十四张两两不等。
- 不同效果按分乘区结算、区内加法累加，顺序不影响结果；构筑深度改由改写发牌规则的元卡承担，它们的价值随检查点严格递减。乘区定义见[卡牌设计](card-design.md)。
- 持续时间有限而赛道分段固定，一张强牌放在 0.25L 还是 0.75L，覆盖的路程完全不同。
- 体力是构筑的预算：高增益卡的代价基本都记在体力上，第三个检查点的选择往往由前两次的体力开销决定。

最小可玩卡池 14 张起步（强效果子集至少 2 张，见第 4 节），覆盖三条构筑轴——瞬时速度（自身加速、强加速但高耗能）、体力经济（体力恢复、减缓消耗、牺牲速度换恢复）、状态反馈（落后追赶），外加提供刷新的那一类。逐张的名称、数值、状态词条与美术需求见[卡牌设计](card-design.md)；这套规模用于验证三条轴都能被玩家感知，不代表最终卡牌体系。

**玩家马的速度与体力计算不得读取任何电脑马的状态**，这是硬约束，也是现在唯一承重的那道墙。电脑马每步读玩家位置来决定自己的目标速度（见第 7 节），玩家这一侧若反过来读电脑马，回路就闭合了：橡皮筋会自激，且再也无法用固定 seed 单独复现与调试电脑马的参数。“落后追赶”因此读的是玩家自身相对基准配速的落后量 `lag(t)`，不是与身前马匹的真实身位差；增益强度在选牌生效时按当时的 `lag` 锁定，不随后续进度变化。

**反方向的写入是允许的，但只限瞬时运动状态。** 玩家的卡可以炸停一匹电脑马、和它交换位置、用重力井拖慢它（见[卡牌设计](card-design.md)），因为这是单向写入，回路并不闭合。边界必须精确：

| 玩家的卡可以写 | 玩家的卡不得写 |
| --- | --- |
| 电脑马的当前速度、当前位置 | `base/min/max/gain/slack/ease/amp/tau` 八个性格参数 |
| 施加给电脑马的外部速度乘子 | 电脑马目标速度函数的任何入参 |

性格参数一旦可写，第 7 节整套标定就失去了对象——那才是这条约束真正保护的东西，而不是“卡牌不能碰别的马”这个表象。电脑马自己吃到的卡（`card_i`）真实作用于它自己的速度，那是每匹马各自闭合的单向通路，不在此限。

负面效果不得使速度永久为零，也不得使任何一匹马无法完赛；瞬时归零后立即按正常加减速重新起步是允许的（【死亡】即如此）。“跳过检查点”在里程制下不可能发生：里程只累计自身位移，任何跳变都不产生里程。

品质仍分普通 / 高品质两级，但在 14 张模型里它只是卡面表现与数值档位，不再参与抽取流程——抽取是对整副卡池的一次无放回定序，与品质无关，唯一的品质约束是末两张取自强效果子集。品质分布不随下注金额变化：下注只从电脑马这一个入口进入系统。

## 7. 电脑马与难度

电脑马不预设成绩，也不按名次预期分配速度。模型是赛车游戏里的电脑车：玩家跑得快，它们能以设定的最快速度追上来；玩家跑得慢，它们也跟着松下来。同时它们也在自己的里程档获得卡牌，且卡牌真实作用于它们自己的速度（`card_i`，见下）。每一步为每匹马 `i` 计算目标速度，再用与玩家相同的有限加减速逼近该目标：

```
gap_i     = posPlayer − pos_i
pull_i    = gain_i × max(gap_i − slack_i, 0)     // 落后超过容忍度才发力追
slow_i    = ease_i × min(gap_i + slack_i, 0)     // 领先超过容忍度才收速
noise_i   = amp_i × N(seed, i, tick)             // 抖动，均值 0，防止贴死玩家
raw_i     = clamp(base_i + card_i + pull_i + slow_i + noise_i, min_i, max_i)
target_i ← target_i + (raw_i − target_i) / tau_i // 一阶阻尼，tau_i 越大变化越慢
final_i   = clamp(target_i × (1 + field_i), 0, vHardMax)  // 外部场，绕过阻尼与 min/max
```

`card_i` 是电脑马自己吃到的卡对速度的临时修正——**电脑马和玩家一样真的吃卡、真的变快**，不是只播特效。`tau_i` 取得足够大是这件事成立的前提：卡牌带来的是一次阶跃，阻尼把它摊成一段缓慢的加速，画面上看是"对手渐渐提上来了"，而不是某一帧突然窜出去。`raw_i` 先钳后阻尼，顺序不能反，否则阻尼的输出会短暂越过 `max_i`。

`field_i` 是玩家的卡施加的外部速度乘子（目前只有重力井）。它**刻意排在阻尼之后、绕过 `min_i` 与 `max_i`**：`tau` 存在的理由是把电脑马自己吃卡的阶跃摊成“渐渐提上来”，而外部场要的正是突然被拽住的戏剧性，走阻尼会把一个 10 秒的效果摊到看不见；绕过 `min_i` 则是为了不让某匹马靠性格参数免疫黑洞。代价是必须补最外层这道全局 clamp，否则场乘子会把速度推出可控范围。没有场作用时 `field_i = 0`，该行退化为 `final_i = target_i`。

`N(seed, i, tick)` 必须是 seed 与 tick 的确定性函数（例如 `H(seed, "noise", i, tick)` 取低位映射到 `[-1, 1]`），**不能用 `Math.random`**。抖动的作用是让并驾齐驱的两匹马不断互相错身，而不是黏成一条线；它一旦成为链外随机，整场就不可回放，第 4 节的记录也随之失去意义。

`slack` 这层容忍带是必需的，不是修饰：没有它，对称的橡皮筋会让四匹马全程贴着玩家跑，冲线名次退化成掷硬币。收速系数 `ease_i` 允许为 0，这样的马领先后不会自己慢下来。

`slack` 与 `amp` 治的是同一个病的两面：`slack` 让马在容忍带内不主动贴上来，`amp` 让已经贴上来的马自己抖开。只有死区没有抖动，马会静止地停在容忍带边缘；只有抖动没有死区，抖动会被橡皮筋不断拉回去。两个都要。

seed 派生的是**四组**参数，不是五组：玩家那匹马的速度由输入决定，没有 `base_i`。四组按玩家选马后剩余 `horseId` 升序依次分配，因此换一匹马只换外观、不换对手（见第 2 节）。派生时约束 `min_i ≤ base_i ≤ max_i`，否则 `base_i` 会被 clamp 掉，下面整套推导的前提不成立。

每匹电脑马的 `base_i`、`min_i`、`max_i`、`gain_i`、`slack_i`、`ease_i`、`amp_i`、`tau_i` 一场内固定、可复现，八个数的组合构成性格：`gain` 高且 `slack` 小是贴身缠斗型，`base` 高且 `ease` 为 0 是一路跑掉的逃马，`max` 高而 `base` 低是掉队后能杀回画面、却始终越不过去的回马枪型，`base` 高而 `gain` 低是前程领跑型。`amp` 大是跑不稳的毛躁马，`tau` 大是提速慢但一旦起来就压得住的重型马。玩家应当能从画面上认出对手的脾气，这是追逐戏剧性的来源。

电脑马在自身检查点从私有牌堆按顺序取牌，**卡牌效果真实进入它们的速度计算**（第 7 节公式里的 `card_i` 项），有演出也有实效。失控由三件事一起挡住：`clamp` 到 `[min_i, max_i]` 防跑飞、高 `tau_i` 阻尼把阶跃摊成缓慢加速、`amp_i` 抖动防贴死。

代价要认：`base_i` 的有效值变成 `base_i + card_i(t)`，第 7 节的稳态分类在一场之内可能变号，因此**手感指标只能靠批量模拟测量，不存在解析预测**。调参时把 `card_i` 的幅度压在「单张牌不足以翻转分类」的量级，否则难度的主导因素会从下注变成电脑马的运气。

一匹马赢不赢得下来，判据不在 `max_i` 而在 `base_i`。设玩家以最优构筑加完美节奏的可持续速度 `vBest` 匀速前进，令 `target_i = vBest` 求稳态，得到三种结局（抖动均值为 0 不移动稳态，阻尼只改变到达稳态的快慢，两者都不改变下表的分类）：

| 条件 | 稳态 | 结果 |
| --- | --- | --- |
| `base_i < vBest` | 贴后平衡，身位差 `gap* = slack_i + (vBest − base_i) / gain_i` | 追得上，越不过去 |
| `base_i > vBest`、`ease_i > 0` | 领先平衡，身位差 `d* = slack_i + (base_i − vBest) / ease_i` | 咬住一个固定身位赢下来 |
| `base_i > vBest`、`ease_i = 0` | 无平衡点，领先持续扩大 | 大幅甩开 |

第一行是关键：这匹马会停在玩家身后一个固定身位上。`pull_i` 随身位缩小线性衰减，恰好在追平前归零，因此它**不会过冲、不会反超**——`max_i` 与 `ease_i` 在这种马身上全程不起作用，`max_i` 只需不低于 `vBest`，否则它连贴住都做不到。所以“再完美也赢不了的马”的唯一判据是 **`base_i > vBest`**。

由此得到四个旋钮的分工，标定时不要拧错：`base_i` 决定赢不赢得下来，`ease_i` 决定赢的幅度（是咬住 `d*` 险胜还是一路甩开），`max_i` 决定掉队的马多快能追回画面，`gain_i` 与 `slack_i` 决定贴多近、咬多紧。后两组只影响追逐好不好看，不改变胜负。

同一套推导还给出玩家操作是否有意义的判据：**一匹马响应玩家操作，当且仅当 `base_i` 落在 [放任配速, `vBest`] 这条带子里**——带内的马完美操作能赢、放任就输给它，带外的马怎么打都是同一个结果。第 6 节要的名次差期望，就等于 `base_i` 落在带内的马的期望数量。

难度的唯一来源是下注金额，作用对象是 `(base_i, max_i, ease_i)` 这一组，三者必须同向移动：`base_i` 分布右移是难度本身，`max_i` 跟着上移才能让掉队的马还追得回来，`ease_i` 压低才能让赢下来的马真正甩开。**只抬 `max_i` 是拧错了旋钮**：`p(B) = P(base_i > vBest)` 一点都不会涨，只会把更多马紧粘在玩家身后，落在响应带外的马反而变多，“怎么打都一样”的局随之上升。

电脑马吃卡使 `base_i` 在一场内有了浮动：有效值是 `base_i + card_i(t)`，因此上表的分类在一场之内可能变号。这不是模型缺陷，是刻意留的变数——对手中途吃到强卡真的会变成威胁。代价是**手感指标只能靠批量模拟测量，不存在解析预测**，这与第 7 节末尾的要求本来就一致；调参时应把 `card_i` 的幅度控制在不足以单张牌就翻转分类的量级，否则难度的主导因素会从下注变成电脑马的运气。

难度因此是概率而非确定分配：每匹马独立抽取，一场里“赢不了的马”有几匹服从二项分布，而不是某档位固定几匹。`B` 低于阈值 `B*` 时 `base_i` 分布的整个上界低于 `vBest`，此时完美操作必然夺冠；`B` 超过 `B*` 后 `p(B)` 从 0 起单调上升，高档位下即使打得完美也可能只争到中游。

手感目标不是任何公式的输出，是靠调上述参数达成、靠批量模拟测量的指标：

- **每个下注档位内**，最优玩法与放任不管的名次差期望都落在 **2–3 名**。这是每档独立的判据，不是全档位平均：玩家一次只体验一个档位，某一档退化成“怎么打都差不多”，平均值救不了它。
- **每个下注档位内**，“怎么打都一样”的局低于 **5%**——这类局的判据是场内没有任何一匹马的 `base_i` 落在响应带（放任配速到 `vBest` 之间），因此玩家怎么操作名次都不变。
- 0 下注档是纯教学局，上面两条不纳入判据：它的目标是稳、好赢、让玩家看清自己在变强，名次差更小或更大都可接受。

低档位为同时满足这两条，`max_i` 的抽样分布会被压窄，性格差异随之压扁。这是可接受的代价：低档本来就是教学档，辨认对手脾气的乐趣留给高档位。

## 8. 结算与社交

结算卡牌显示：比赛 ID、结算 tx 及浏览器链接、名次、至多三次选择（含放弃与因里程不足而未发生的那次）、下注额、总返还、净盈亏和交易状态。金额定义以[经济结算](chain-and-economy.md)为准。

玩家冲线立即播放庆祝或失落动画；资金状态用一枚短印章表达（结算中／已结算／结算失败），不能展示虚构 tx 或把预计奖金标成已到账。结算失败时，完整说明与「重试结算」另起一处放在按钮行下方，不挤进印章本身；交易提交后显示 tx，最终确认后显示实际已到账/可领取状态。尾场演出或网络延迟不能阻塞关闭面板和后续恢复查询。
