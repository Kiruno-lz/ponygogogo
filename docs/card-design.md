# 卡牌与效果系统设计

本文承载[玩法设计第 6 节](game-design.md)的展开：效果原语、状态与装备词条、卡牌清单与美术需求。玩法总纲（里程检查点、牌堆发牌、慢放、体力预算）以玩法设计为准，本文不重复。事件求时器、效果实例与扩展点在[效果系统架构](architecture/effect-system.md)。

## 1. 设计目标

**卡牌是本作的核心玩法，创意来源是 meme。** 一张卡成立的第一判据不是数值曲线，是玩家看到卡面的瞬间认出这是什么梗、并且知道接下来会发生什么好笑的事。数值服务于这个瞬间，不反过来。因此本文允许出现「30 秒后必定死一次」这种在纯平衡视角下不合理的设计——它是梗的一部分。

**状态之间的交互是构筑的第二层。** 【起飞】免疫炸弹不是特例补丁，是这一层的第一个例子：卡牌之间通过公开的状态词条互相咬合，玩家自己发现「原来能飞就炸不到」比卡面上写十行说明有效得多。后续卡牌应当继续往这一层加，而不是继续堆纯数值。

每场仍最多获得三张牌。两张可以建立配合，第三张根据体力、剩余里程与对手状态选择补给、反制或冲刺；不通过增加选牌次数、职业分类或指定三张新卡的套装判定制造构筑深度。

三条贯穿全文的规则：

- **效果可叠加，且互相独立计算持续时长。** 每次选牌产生的是独立的效果实例，同类效果不合并、不刷新时长、不互斥。玩家手上同时挂着三条各自倒计时的增益是常态。
- **全部时长以模拟时间计**，随选牌慢放同步减速。按现实时间计的只有选牌的 20 秒限时和 C-04 自动面板的 3 秒（[玩法设计 §4](game-design.md)）。
- **规则与表现单向依赖。** 装备图、拖尾和交换音效都不进入比赛求时计算；美术或音频资源缺失时规则照常运行。

## 2. 与规则内核的边界

三条边界决定了卡牌能做什么、不能做什么。它们在[玩法设计](game-design.md)定义，这里只说清楚每条为什么长成这样——照着抄容易，改错也容易。

### 2.1 跨马交互是双向的

玩家的卡可以炸停一匹电脑马、和它交换位置、用重力井拖慢它；反过来，电脑马抽到的卡同样可以作用于玩家。任何卡都不得写入场冻结的性格参数，包括基础加速度 `a_i`、基础速度上限 `C_i` 与体力参数。

**跨马效果不等于电脑马追赶玩家。** 炸弹、交换、重力井可以改变别的马的状态；电脑马下一运动区间只从自己的性格、体力和明示跨马效果继续演进。

性格参数之所以单独禁死，正是因为它们是标定的锚点。炸弹、交换、重力井、天气都只改瞬时量，扰动的是收敛过程而不是分类；性格参数一旦可写，连定性分类都不剩了。

### 2.2 里程与位置是两个量

检查点按每匹马自身跑过的里程触发，位置跳变不产生里程（[玩法设计 §3](game-design.md)）。对卡牌设计来说，这条带来两个必须记住的后果：

- **传送类卡牌不需要任何特殊规则。** 来回交换刷不出第四次抽卡，被换到后面也不会重复触发已消费的档位。
- **提前冲线的马拿不满三次抽卡。** 把自己换到终点前，就是用一次抽卡机会换一段捷径。这个取舍必须写进卡面描述，不能让玩家事后才发现。

### 2.3 负面效果的下界

负面效果不得使速度永久为零，也不得使任何一匹马无法完赛。**瞬时归零后立即重新起步是允许的**——【死亡】正是如此：基础速度归零，只能按性格加速度重新攀升，代价是数十秒以上的追赶时间，但马仍会完赛。

## 3. 效果原语

一切卡牌效果由九类原语组合而成。新增卡牌若需要第十类原语，是架构信号，先改[效果系统架构](architecture/effect-system.md)再加卡。

| 原语 | 含义 | 是否有视觉资源需求 | 本文实例 |
| --- | --- | --- | --- |
| `Modifier` | 对速度、体力等连续量的乘区贡献 | 否（通常由携带它的装备/状态表现） | 各类「加速 X%」、体力消耗减半 |
| `Status` | 布尔或层数标记，可被其他原语查询 | 按可读性选择 HUD 或场景表现，不要求都画在马身上 | 【起飞】【运气E】【重生】 |
| `Equipment` | 挂到骨架插槽的限时对象，携带若干 `Modifier`/`Status` | 是（必须有图与动画） | 【火箭喷射器】【史瓦西黑洞】【风火轮】 |
| `Ability` | 自动触发的规则能力，不覆盖 gogo 输入 | 可用音效提示；不要求额外视觉特效 | 【拍手交换】 |
| `Hazard` | 放置在赛道坐标上的独立实体，被马匹触碰时结算 | 是（赛道上的物件 + 触发动画） | 炸弹 |
| `Field` | 生效期间按持有者与目标的实时距离连续改变百分比修正 | 不要求范围特效；由装备外观表达来源 | 重力井 |
| `DrawRule` | 修改牌堆游标的取牌行为 | 是（选牌面板的形态变化） | 【刷新】、自动抽取、断卡 |
| `Environment` | 比赛级的全局状态，**单槽**，新的完整替换旧的 | 是（全场天气表现） | 【起风了】的风向 |
| `Trigger` | 挂一个条件与一段结算，条件满足时触发一次 | 否（由被触发的效果表现） | 运气E 到期死亡、火焰 7 层爆发 |

### 3.1 效果实例与独立计时

每次选牌生成一个或多个 `EffectInstance`：

```ts
interface EffectInstance {
  instanceId: number        // 本场自增；同一事件类内按它升序处理
  sourceCardId: string
  primitive: PrimitiveKind
  appliedAtTime: Fixed
  duration: Fixed | null   // null = 持续到比赛结束；数值单位为模拟时间
  payload: unknown          // 该原语的参数
}
```

这是概念模型。求时器的实现是 `src/race/paid/solver.ts` 的 `Instance`：种类为 `buff/bonus/equip/ability/respawn/watch/fixed`，时间为毫秒整数，永久用 `NEVER`，见[效果系统架构 §3](architecture/effect-system.md)；表现层的 `EffectInstance` 只是由事件日志生成的快照。

默认叠加策略是 `independent`：不查重、不合并、不刷新时长。两张都给加速的卡同时在手，就是两条各自倒计时的实例，到期各走各的。

但「独立」不是唯一策略——有些效果占用的是**唯一资源**（一个插槽、一片天空），它们必须显式声明别的策略。三种策略覆盖当前全部情形：

| 策略 | 语义 | 用在哪 |
| --- | --- | --- |
| `independent` | 各自计时、各自生效，互不干扰 | 默认；全部纯增益 |
| `replace` | 单槽，新的完整顶掉旧的，旧的立即失效 | `Equipment` 同插槽（§5）、`Environment` 全局槽（§7.4） |
| `refresh` | 重置已有实例的剩余时长，不新增实例 | 【以旧换新】刷新自己的装备 |

**`replace` 是有损的**：同插槽新装备顶掉旧装备后，旧实例直接消失，不暂停、不排队。

【以旧换新】刷新当前装备的到期时刻，保留实例、持有者、插槽与已消费的周期事件，不视为重新获得装备；【改装达人】不因这次刷新再次触发。装备回收另记 `recycled` 移除原因，与自然到期、覆盖和偷取区分，不能用自然到期回调代替拆除。

### 3.2 基础速度、百分比与固定值

马的性格给出基础加速度 `a_i` 与基础速度上限 `C_i`；体力足够时基础速度 `b_i` 随模拟时间增长，最多到 `C_i`。**百分比卡不改变 `C_i`，而是乘当前 `b_i`；固定值卡加在百分比结果之外。**

```text
P_i = Σ 同时生效的百分比速度效果
K_i = 已获得、尚未到期且未被明示清除的有符号固定值速度贡献之和
v_i(τ) = max(0, b_i(τ) × (1 + P_i) + K_i − E_i)
```

因此 +30% 与 +40% 同时生效为 `b_i × 1.70`，若另有 +10 固定值则为 `b_i × 1.70 + 10`，**不是** `(b_i + 10) × 1.70`。百分比效果按各自模拟时长进入/退出 `P_i`；固定值 `+10/+20` 在卡牌生效时给 `K_i` 加一次，后续不按帧重复。风火轮每次爆发按同一固定值事件给 `K_i` 加 `ΔvWheel`（规则表 `fixedSpeed`）。基础上限仅约束 `b_i`，卡牌修正后的总速度可以高于 `C_i`。

重力井和天气仍提供百分比速度效果，但与卡牌百分比进入同一个加算和；**重力井必须按实时距离连续重算**，在其有效期间对五马耦合轨迹积分，不允许锁定触发时距离。【死亡】在触发时清空当时基础速度和已经获得的固定值速度增量；卡牌本身不移除，但此前的一次性固定值事件不重放。【力竭】期间加速度为 0，并提供 10 单位有效速度下降，直到体力回满退出；详情见[玩法设计 §5](game-design.md)。

规则表（`src/race/paid/cardRules.ts`）里与速度公式相关的字段对应如下：

| 规则表字段 | 语义 |
| --- | --- |
| `pBps` | 在效果有效期间向 `P_i` 加该 bps，可为负 |
| `fixedSpeed` | 有符号的固定值。C-17、C-18、C-21 获得时向 `K_i` 加一次；C-40 获得时先加 −20，`triggerFixedSpeed` 是每越过一个里程阈值的追加写入；C-11 每次爆发加一次；C-38 在死亡清零后写入有来源与期限（`triggerDurationMs`）的固定值贡献 |
| `costMultiplierBps` / `costDeltaBps` | 体力消耗修正，与其他修正加算，受 10% 下界约束 |
| `regenBonusBps` | 体力恢复加成，单独加算 |
| `bonusBps` / `fallbackBps` | 阶段或触发后的追加百分比 / 条件不成立时的备选百分比 |

规则表没有速度上限修正，也没有百分比乘法字段：所有百分比只加算一次，避免产生第二套组合口径；需要这类效果时先改规则版本。

门控（`gated` 实例）决定效果是否进入当前区间：起飞、亢奋、毛色与装备条件在每个运动区间开始时重算。所有分段参数用定点整数/有理数表示；根的取整、同刻事件优先级与积分舍入必须由规则版本冻结，不依赖动画帧率或 Solidity/JavaScript 各自默认浮点运算。

固定速度使用赛道单位/秒，体力使用满值 1000 的规则尺度；实现统一换算为定点整数。【登神长阶】的 −20 是一次有符号固定值写入，不改基础速度或上限；【嗯，来劲了】的 +120 是有来源与 30 秒期限的固定值贡献。死亡清除当时正负固定值，失效的贡献后续到期不得再扣一次，旧写入不重放。

负固定值使速度表达式跨过 0 时，求时器在区间内解析处理过零，只积分 `max(0, v)`；不能产生负位移或倒退里程。有符号速度字段、贡献移除与整数取整必须同时用于 TS 与 Solidity。

体力消耗修正加算后设 10% 下界：`costFactorBps = max(1000, 10000 + ΣcostDeltaBps)`，`costPerMs = floor(baseCostPerMs × costFactorBps / 10000)`。【火箭喷射器】贡献 −5000，【省流模式】−4000，【狂暴引擎】+5000，只在各自有效期进入和；单件火箭消耗为基础的 50%，火箭加狂暴引擎为 100%。恢复加成单独加算，不与消耗修正混算。

【梭哈】先快照 `paid = min(S,300)`，再扣除体力并挂载 `floor(3500×paid/300)` bps 的速度增益，持续 12 秒；实现中的 `S/paid/300` 统一使用微体力。普通瞬时恢复钳在体力上限，已有超上限体力不被裁低；只有明示可超上限的【肾上腺素】能增加 overcap。恢复未达到满值时，不自动解除已经生效的【力竭】。

上述边界由 `src/race/paid/resources.test.ts`、`newCards.test.ts` 与 `tests/contracts/PaidRaceNewCards.t.sol` 验证，覆盖体力 0/150/300/1000 的支付、消耗加算与下界、恢复与 overcap、贡献到期/死亡同刻和负固定值过零。固定向量 `b=20`、+30%、+40%、+10 在两种实现中同得 `v=44`；`tests/vectors/paid-race-v4.json` 的 355 组向量逐字段比较事件（含资源写入与固定贡献）、检查点、五马冲线与结算结果，包含风、连续重力井和装备转移。

这张表列出卡池所需机制及其承载。

「瞬时动作」不单列为原语：放炸弹、转移装备、交换位置、回满体力都是效果实例挂载那一刻的一次写入，求时器的 `applyCard` 在挂载时直接做，不需要新东西。

| 机制 | 承载（设计词汇，实现见效果系统架构 §3） | 代表卡 |
| --- | --- | --- |
| 自身数值修正，三种算子 | `Modifier.op` | 全部加速卡、薄肌系列（`add`） |
| 一次性固定值速度增量与体力修正 | `Modifier.op: add` 的触发写入 / `Modifier.target` | C-11 爆发、C-17 / C-18、C-14 / C-15 |
| 条件生效（状态门控） | `Modifier.gate` | 起风了 |
| 布尔状态 | `Status` | 起飞、运气E |
| 装备、插槽、挂点 | `Equipment` | 四件装备 |
| 自动触发能力 | `Ability` 与模拟时间事件 | 不义游戏 |
| 赛道实体 | `Hazard` | 炸弹来咯 |
| 区域场 | `Field` | 重力井 |
| 全局环境、单槽替换 | `Environment` | 起风了 |
| 跨马状态转移 | `Equipment` 转移 | 顺手牵羊 |
| 条件触发（到期、周期、资源） | `Trigger` | C-02、C-11、C-24 |
| 发牌规则修正 | `DrawRule` | 三张元卡 |
| 一次性资源写入 | 挂载时的一次写入 | 肾上腺素 |
| 资源越过上限 | 体力模型的 overcap 分支 | 肾上腺素 |
| 纯外观状态 | 零 `Modifier` 的 `Status` | 黄毛、染成绿的 |
| 规则与渲染双向的剥夺 | `blindedPro` 免疫他马炸弹、风与交换，渲染层隐藏他马 | 理解孙学 |
| 组合 / 套牌判定 | `Trigger` 的 `setMatch` 条件由合约从已锁定卡牌判定 | 版本答案（§7.6） |
| 特殊结算名次 | 先算五马物理冲线排序，再由经验证的组合分支改写结算排序 | 版本答案（§7.6） |
| 核心规则抑制 | 【亢奋】实例的 `wired` 贡献：获得时结束【力竭】，并使体力见底不再排程 | 咖啡因过量 |
| 通用效果移除 / 驱散 | 按实例结束，原因为到期、覆盖、偷取、回收、消费、死亡或冲线 | 装备转移、垃圾佬、名刀司命 |
| 死亡替换反应 | 永久 `watch` 实例与 `GUARD` 消费事件；免疫先于拦截 | 名刀司命 |
| 有符号、有限期固定速度 | 有来源的 `fixed` 实例、到期移除与死亡清除 | 嗯，来劲了、登神长阶 |
| 消耗支付与通用消耗修正 | 瞬时支付快照、资源事件与消耗加算和 | 梭哈、省流模式、狂暴引擎 |
| 阶段、资源和里程事件 | `watch` 模拟时间边界、资源首次阈值与递增 `dist` 阈值 | 摸鱼是为了更好地冲刺、备用粮、登神长阶 |
| 装备获得、刷新与回收 | 装备获得时的监听、实例期限更新与 `recycled` 移除原因 | 改装达人、以旧换新、垃圾佬 |
| 否定状态与毛色/装备门控 | 每个运动区间重算起飞、亢奋、当前毛色与全身装备 | 纸飞机、接地气、跑马灯、空手道 |
| 跨马目标与名次快照 | 选中时筛选一次并冻结目标/分支 | 年轻人不讲武德、赢麻了 |
| 主动放弃反应 | `forfeit-tx` 原因与监听实例一次性消费 | 躺平是种智慧 |
| 自身位移 | `laneIndex` 与 `pos` 的规则状态转移 | 不义游戏 |

死亡替换反应使用【名刀司命】的明确顺序（§4），不扩展成任意效果的复制或通用拦截系统。周期与条件反应只能在规范事件点触发，不按帧重复查询后写入。

## 4. 状态词条

状态是可被其他效果查询的标记，是卡牌之间产生化学反应的接口（§1）。带 † 的条目是本文补充的建议默认，非用户原始要求。

### 【起飞】Airborne

马悬浮于赛道半个马身高度。

- 本身不改变速度；速度增益由携带它的卡另行给出。
- **免疫全部 `Hazard`**：悬空的马不触发地面炸弹。这是构筑交互层的第一条正式规则，不是特例。
- 视觉：马整体 y 偏移，地面投影缩小并偏移；全部挂载装备跟随偏移。

### 【死亡】Death

- 当前速度立即归零，**位置不变，不退回原点**。
- 获得 5 秒【重生】状态。
- 不清除装备、其他状态或尚未消费的触发器；清除当时基础速度与全部正负固定速度贡献。【嗯，来劲了】在实际死亡清零后才写入新贡献。
- 不影响里程：里程只累计自身位移，速度为零的那段自然不产生里程，抽卡机会因此被推迟而不是被取消。

每次死亡请求依次处理：已冲线则忽略 → 现有【重生】免疫则忽略 → 有未消费的【名刀司命】则消费并拦截 → 执行速度清零并挂载【重生】→ 触发实际死亡反应。拦截不产生死亡/重生，不触发【嗯，来劲了】；同刻多次请求按冻结事件顺序分别处理，名刀只挡第一件本来会生效的请求。

### 【重生】Respawning

- 持续 5 秒，视觉为消失/出现的闪烁。
- † 期间免疫再次【死亡】。没有这条，多枚炸弹会连锁把一匹马按在原地，那既不好笑也不可控。

### 【运气E】Luck E

- 厄运标记。持续期间，任何随机判定对该马取最差结果（当前卡池尚无此类判定，字段为后续卡预留）。
- **到期时必定提出一次【死亡】请求**，按重生免疫与名刀拦截顺序处理。没有免疫或拦截时必定死亡，不是概率事件。

### 【火焰】Burning（表现读数）

- 风火轮从获得（或翻新）时刻起每 7 秒模拟时间爆发一次：求时器在 `start + 7 s × (已爆发次数 + 1)` 早于装备到期时，给 `K_i` 加 `ΔvWheel`（+10），加入百分比结果之外；总速度超出性格基础上限也不扣回。此增量不消耗额外体力。
- 未翻新时一件风火轮在 30 秒内最多爆发 4 次（7/14/21/28 秒）；【以旧换新】延长期限后继续按原相位触发。已获得的速度增量按一次性事件保留，直至【死亡】或其他明确扣速事件。
- 火焰层数不是求时器状态，只是 7 秒周期内的派生读数（每秒 +1 层，满 7 层爆发后清零）；隐藏它不影响规则。
- 视觉：火焰层数和爆发不在马身显示；四蹄风火轮与【起飞】表现保留。

### 【亢奋】Wired

- 体力消耗到 0 后不再继续消耗，体力停在 0，不产生负值或欠债。
- **【力竭】状态被抑制**：体力为 0 时不进入【力竭】：不失去基础加速度，也不承受力竭期间的 −10 速度；已有【力竭】被移除，体力保持当前值。【亢奋】结束后若体力仍不足支付下一事件区间 的消耗，立即按正常规则进入【力竭】。
- gogo 镜头点击始终没有体力代价，与【亢奋】无关。
- 视觉：体力条空了但在发光，马眼变成漩涡。

### 【毛色】Coat（外观状态）

- 携带一个颜色值，**没有任何数值效果**。
- 它用于外观、【版本答案】的构件表达与【跑马灯】门控。【毛色】自身不提供数值，跑马灯根据当前颜色提供数值；版本答案仍按获得 cardId 判定（§7.6）。
- 同时只有一个毛色生效（`replace`，§3.1）：后染的盖掉先染的。
- 视觉：头顶出现一撮与颜色对应的尖发（黄毛为金色、染成绿的为草绿），随马体升降与翻面，不改马体贴图；装备与拖尾不受影响。同时只显示当前毛色对应的那一撮。

### 【目中无人】BlindedPro

- **既作用于渲染，也作用于规则**：其他马照常跑、照常放炸弹，但不会和你交换位置，炸弹也不会炸到你，其他马引发的全场天气效果，也不会影响到你。
- 【年轻人不讲武德】筛选前方目标时排除拥有【目中无人】的马；该免疫不扩展为对所有外部 Modifier 的通用免疫。
- 其他马的精灵、装备与拖尾全部不渲染；HUD 名次条保留，否则玩家会彻底失去方向感。视觉：其他赛道空着，只剩赛道线与场景。

### 【名刀司命】Death Guard

- 不占装备插槽，持续到比赛结束或消费；拦截下一次本来会生效的死亡请求，仅一次。
- 已有【重生】免疫的请求不消费名刀；取得时已经发生的死亡不撤销。
- 视觉为一次护符破碎，不把护符画成可窃取、可刷新时长的装备。

### 【来劲】Post-Death Burst

- 【嗯，来劲了】在取得后 50 秒内监听下一次实际死亡，窗口为 `[appliedAt, appliedAt+50s)`；末端同刻死亡不触发。触发一次后监听立即消费。
- 死亡清零后生成固定速度 +120 的独立贡献，有效区间为 `[deathTime, deathTime+30s)`；后续死亡可以清除它，不恢复监听额度。
- 视觉只在实际触发时播放重启爆发；监听图标与加速倒计时分别显示。

## 5. 装备词条

装备是挂到骨架插槽的持久对象，**每一件都必须有图与动画**，资源清单见 §9。

| 装备 | 插槽 | 携带的效果 | 时长 |
| --- | --- | --- | --- |
| 【火箭喷射器】 | `torso` | 体力消耗修正 −50%（§3.2）、加速 15%（百分比速度） | 40s |
| 【史瓦西黑洞】 | `torso` | `Field`：重力井 | 10s |
| 【风火轮】 | `hoof_fl` `hoof_fr` `hoof_bl` `hoof_br`（四件同时） | 常态【起飞】；每 7 秒爆发一次，直接增加一次当前速度 | 30s |
| 【彩虹拖尾】 | `tail` | 加速 10%（百分比速度） | 60s |

装备到期时播卸载动画；效果在规范到期时刻立即失效，不等动画结束。
同一插槽同时只能装一件装备，新的覆盖旧的。覆盖时，旧的先完整执行卸载，再添加新的。

【空手道】检查全身全部规则装备槽，任一有效装备都会关闭无装备增益；不只检查躯干。四个风火轮贴图属于一件四蹄规则装备，回收或刷新只处理一次。【名刀司命】等普通状态不计入装备。

【以旧换新】在生效时快照持有者的全部有效装备，将每件 `expiresAt` 改为 `now + equipmentBaseDuration`。实例 ID、周期相位、火焰与已消费事件保留；不重放挂载动作、不恢复已获得固定速度，也不触发改装达人。刷新后尚存的周期能力继续到新期限，事件次数上界按新期限重算；已经自然到期的装备不能复活。

【垃圾佬】只回收自己有效装备中剩余时长最短的一件；平手按实例 ID 升序，永久装备视作剩余时长无限。回收立即移除该装备的连续贡献、起飞来源、场与后续周期事件，已经发生的一次性固定加速保留。

【改装达人】取得时若已有任意有效装备，触发一次；之后每个实际获得装备事件再触发一次，包括正常挂载与窃取后挂载。一次覆盖只算新装备获得一次；一件四蹄装备不按贴图数算四次。持续到比赛结束，不另设两次上限；刷新、渲染重挂与恢复回放不算获得。

## 6. 自动触发与随机交换

gogo 始终只控制镜头，不被卡牌占用或重绑定。【拍手交换】按 2 秒模拟时间自动触发；【风火轮】像【史瓦西黑洞】一样在装备有效期内常态生效。两者都不读取点击或长按，效果实例各自计时。

- 【拍手交换】获得时尝试一次，此后每隔 2 秒模拟时间尝试一次；30 秒到期的同刻先失效，不再触发。尝试序号从 0 递增，即使目标已冲线或被免疫也消耗该次尝试。
- 【风火轮】装备有效期间常驻【起飞】；每 7 秒爆发一次，直接给当前速度加一次固定增量。每次爆发只结算一次，装备到期不撤销已获得的速度增量。
- 【登神长阶】取得时快照 `dist₀`，在 `dist₀ + k×0.20L`（`k=1..4`）各奖励固定速度 +30 一次。交换不写里程、不重置阈值；死亡不重置已消费次数。没有位置跳变时，在三个检查点分别取得，冲线前通常可兑现 3/2/1 次；被换到后方而跑出更多里程时仍最多四次。
- 【摸鱼是为了更好地冲刺】的两个阶段在取得后第 6 秒交接，不重叠；死亡不暂停或重启阶段。【备用粮】在取得后 20 秒内首次 `stamina ≤200` 恢复 300，取得时已满足则当刻结算；末端不含，触发前先消费额度，避免恢复后的资源重算再次触发。

起飞、亢奋、装备和毛色门控只决定当前贡献，不反复创建实例；来源获得、移除、到期或转移时重算。【年轻人不讲武德】和【赢麻了】只在选中时读取全场规则状态，之后不随名次、镜头或距离改靶/切换分支。

### 6.1 【交换】的完整定义

`horseId` 是身份，`laneIndex` 是可变的上下站位（[玩法设计 §2](game-design.md)）。【交换】在规则层交换两匹马的 `pos` 与 `laneIndex`；里程 `dist`、速度和冲线兜底排序保持不变，画面按新的 `laneIndex` 渲染。

- 每次从自己当前 `laneIndex` 以外的四条赛道中等概率抽一条：将四个目标 `laneIndex` 升序排列，以 `H(seed, blockhash(b_card), i_card, "swap", triggerIndex) mod 4` 取下标。`b_card` 永远是获得 C-09 那笔选择交易的实际入块号，后续选牌不更换这张卡的随机锚；`triggerIndex` 连续递增。四个方向各占 1/4，不由本地时间或镜头决定。
- 双方交换 `pos` 与 `laneIndex`，各自速度与里程不变，不出现规则层过渡动画。
- 镜头通过快速平滑移动跟随玩家马；镜头动画不进入求时器，掉帧或关闭动画不改变结果。
- 若抽中的赛道已有冲线马，或持有者或目标已冲线或因【目中无人】免疫交换，本次触发空过、不重抽；不得交换已冲线马或改写已确定名次。

这张卡仍是双向赌博：四条其他赛道上的马可能在前面，也可能在后面。玩家不能通过点击次数或时机改变交换次数或目标。

## 7. 场上实体、区域场与发牌修正

### 7.1 炸弹（Hazard）

「炸弹来咯」的效果：**给其他四条`laneIndex`赛道各放置一枚炸弹，位置是放置瞬间触发卡牌的 `pos`。**

- 非【起飞】的马越过自己当前赛道上的炸弹 `pos` 时触发，结算一次【死亡】，炸弹消失。
- 【起飞】状态的马不触发（§4）。
- 炸弹是中立对象，可以炸到触发者（通过【交换】切换了赛道），触发这张卡牌效果的也可以是电脑马。
- † 炸弹永久留在赛道上直到被触发或比赛结束，无寿命。
- 判定用位移区间而非坐标相等：高速下按坐标相等会漏判（见[效果系统架构 §5](architecture/effect-system.md)）。
- 视觉：赛道上的炸弹、引信循环动画、爆炸动画。

### 7.2 重力井（Field）

装备【史瓦西黑洞】在躯干，持续 10 秒：

- **前方**的马受到减速，**后方**的马受到加速，两者都按距离衰减，最高 30%。
- † 衰减为线性：`k(τ) = 0.3 × max(0, 1 − d(τ) / R)`，`d(τ)` 是该时刻目标与持有者的绝对距离；`R` 为规则表 `radiusMicro`，即 8000 单位（赛道的 8%）；此处的 `R` 不是 §3.2 的偿付预留。
- 每个目标在任意模拟时刻的有符号修正为 `p_target(τ)`：前方为 `−k(τ)`，后方为 `+k(τ)`，与其他百分比速度效果直接加总。`k(τ) = 0.3 × max(0, 1 − |pos_target(τ) − pos_owner(τ)| / R)`；两马恰好同一 `pos` 时该目标按后方处理，取满强度 `+30%`（规则表 `overlapBps`）；越过场源后符号翻转。前后关系、距离与作用对象随运动和交换实时变化，10 秒到期后立即移除。

链上在重力井有效期间对由 `p_target(τ)` 耦合的五马运动做确定性数值积分，不能为了闭式解将效果改成触发时快照。若装备被【顺手牵羊】转移，旧场立即移除，以新持有者为场源继续按实时距离计算，并按转移后的完整时长重新计时。浏览器与合约使用同一冻结积分规则，不以渲染帧率计算场效果。

**后方加速是这张卡的真实代价，不是副作用。** 它把身后的追兵拉近，换取把身前的对手按住 10 秒。

### 7.3 发牌修正（DrawRule）

发牌是一副 14 张有序牌堆加一个游标（[玩法设计 §4](game-design.md)），因此发牌修正全部是对**游标**的操作，不是对概率的操作：

| 修正 | 来源 | 定义 |
| --- | --- | --- |
| 【刷新】 | 海贼王的宝藏 | 展示的三张卡牌下方都出现可点击的刷新按钮，被刷新的卡牌由反向游标取出的 `deck[--tailCursor]` 顶替，正向游标不受影响，另外两张不动。† 刷新不重置 20 秒限时；† 刷新额度可累计并在任意后续检查点使用；† 额度用尽、同一位置已刷新或反向游标不能再越过正向游标时，该位置不可再刷新 |
| 自动抽取 | 选择困难综合症 | 后续检查点不展示面板，由最近一次已锁定选择锚的 `H(seed, blockhash(b_anchor), i, "autopick", eventIndex)` 从展示的三张中直接选定一张。† 自动抽取仍触发慢放与卡面展示动画，但不接受输入——玩家要看到自己被剥夺了选择权，这才是梗。† 剥夺的是选择权也包括刷新权 |
| 效果加成 | 选择困难综合症 | 后续获得的每张卡**额外附带 +20% 加速**（百分比速度），持续时间跟随该卡自身主效果时长；† 瞬时卡按 20 秒计 |
| 断卡 | 最后的波纹 | 后续检查点不再展示卡牌，† 游标停在原地不再前进。结算记录中该次选择记为 `null` 且原因为 `cut`，与超时的 `timeout`、主动放弃的 `forfeit-tx` 区分 |

自动抽取不等待新的交易或未知检查点区块：它使用获得【选择困难综合症】时已锁定的随机锚及当前检查点序号，故链上可从已有输入唯一推导结果，不让任何人通过拖延“自动选择交易”改变随机值。

【躺平是种智慧】只监听取得之后的检查点，持续到比赛结束或首次主动放弃。触发依据规范选择记录 `forfeit-tx`，恢复 300 体力并挂载 +25% 速度 12 秒，消费一次；超时、自动选择、断卡和未达到检查点均不触发，也不新增选择或随机锚。第三检查点取得时不再有兑现机会，但仍承受立即 −10% 速度 8 秒的代价。

**「海贼王的宝藏」在牌堆模型下只需要一个效果，不需要两个。** 它原本的设计是「更可能出现高品质 + 刷新一次」，但最后两张牌默认的就是强卡，这里的刷新选中的就是从牌底开始计数的卡。【刷新】使用一个独立的游标，是从牌底向前的操作，和游标是正相反的。

**「最后的波纹」在第三个检查点拿到时没有代价，这是玩法而不是漏洞。** 识别出「最后一个路口可以白嫖 40%」本身就是构筑理解的一部分，不加可用性限制、不做特判。

### 7.4 环境（Environment）

环境是**比赛级的全局状态，只有一个槽位**。它不挂在任何一匹马身上，作用对象由它自己声明；新的环境效果完整替换旧的，旧的立即失效（`replace` 策略，§3.1）。

【起风了】是第一张环境卡：

- 随机选一个风向，随机源 `H(seed, blockhash(b_source), checkpointIndex, "wind", eventIndex)`；玩家卡的 `b_source` 是选中它的入块号，电脑马私有卡的 `b_source` 是入场块号。
- **只作用于全场处于【起飞】状态的马**，玩家与电脑马一视同仁——这是以【起飞】状态为门控的百分比效果的第一个实例。
- 逆风（终点吹向起点）提供 −10%，顺风（起点吹向终点）提供 +10%，与其他同时生效的百分比直接加总后乘当前基础速度。
- **持续时间无限**，直到比赛结束或被下一个环境效果覆盖。

环境槽是单槽而不是多层叠加，理由不是省事：天气是玩家一眼要能读懂的全局信息，两层风同时吹没有任何视觉表达方式。单槽同时也给了后续环境卡一个天然的互动点——用一张新天气盖掉对自己不利的旧天气，本身就是一步棋。

**这是第一张棋盘状态卡，不是自增益卡。** 它可能对自己是负的、对对手是正的；方向随机，所以拿它就是赌。它也是第一张**必须配合别的卡才有意义**的牌：没有任何起飞手段时它完全空转。这两点让它在卡池里承担的角色与其他卡都不同——先有【中国马能飞】或【风火轮】，它才是一张牌。

### 7.5 跨马状态转移

【顺手牵羊】要把一件装备从别人身上摘下来装到自己身上，这是第一个**转移**而非施加的效果，它对架构提出两条新要求：

- **电脑马必须持有真实的 `Equipment` 实例**，不能只是视觉图层。否则场上无物可偷。
- **装备可以被移除**，移除时它携带的全部 `Modifier` / `Status`一并失效，原持有者的 `card_i` 贡献同步下降。

转移规则：

- 从「全部其他未冲线的马身上的全部装备实例」里等概率取一件，随机源 `H(seed, blockhash(b_source), checkpointIndex, "steal", eventIndex)`；来源锚的归属同 §7.4。
- 装到自己身上，作为新实例，**时长为该装备的完整时长**（同插槽按 §5 覆盖）。
- 若与自己已有装备同插槽，按 §5 的插槽规则新的覆盖旧的。
- **场上没有任何装备时，这张牌没有效果**，也不返还、不补抽。

**空过是设计的一部分，不是待修的缺陷。** 第一个检查点场上通常一件装备都没有，这张牌那时是废纸；到第三个检查点，四匹电脑马身上多半挂着东西，它就是全场最强的一张。**它的价值随检查点递增，与三张元卡正好相反**——一副牌里同时存在两种斜率，玩家才需要真的判断「现在是不是拿它的时候」。

### 7.6 组合彩蛋：版本答案

同时持有【薄肌】或【薄肌 pro max ultra】、【黄毛】、【理解孙学】三张时，触发【版本答案】的卡面、HUD 与结算海报彩蛋。组合不改马的运动状态、五个 `finishTime_i` 或物理冲线排序 `rawRank`；合约从已锁定的实际获得卡牌检测组合，将玩家置于 `settlementRank` 第一，其余四匹马保持 `rawRank` 中的相对顺序。奖金与战绩使用 `settlementRank`。这是一条可复算的卡牌规则，不接受浏览器提交的 `forcedRank` 或胜者声明。

组合判定在第三个构件按规范选择时间生效时执行一次；没有凑齐则不触发，电脑马不触发。浏览器与合约从三次选择判定彩蛋；合约据此得到的 `settlementRank` 即赔付依据，浏览器只复算、不提交判定。三个构件仍须落在不同检查点供玩家各选一次；刷新仍按既有牌堆规则，不为凑组合增补候选。

### 7.7 卡池下限

[玩法设计 §6](game-design.md) 的静态断言是：**总卡池 ≥ 14 张，其中强效果子集 ≥ 2 张。** `rare` 即强效果子集，只通过牌堆末两张保底参与抽取，其余不影响发牌。

**强效果子集就是 `rare` 品质的卡集合**，不引入第三个维度。玩家在图鉴里看到的金框卡，就是牌堆末两张保底会给的卡，两个概念指同一件事；拆成两套标记迟早会出现「金框但不保底」的卡，那是纯粹的认知负担。

事件求时器运行时卡库为 **40 张（C-01 至 C-40）**，共 23 张 rare、17 张 common，全部有正式效果。规则表同时生成 rare/CPU mask、Solidity 参数和 ID 边界；CPU 排除 C-29/C-39 及既有禁用卡。牌堆仍为 14 张、末两张 rare 保底，正常三个面板展示九张，每场选择至多三张；扩池不补发第四次选择。

每场有 26 张制作卡库中的卡不进入 14 张候选牌堆。共享起飞、体力、装备和毛色条件提供可替代配合；【版本答案】仍需三个构件各落在不同检查点。

`scripts/analyze-paid-card-builds.ts` 使用完整 40 张卡池、四档赛程、五匹玩家马、真实检查点窗口、刷新及 CPU 选择，对 80 个派生种子执行固定策略；结果保存在 `tests/vectors/paid-card-builds.json`，可用 `--check` 复算。`acquiredBoth` 统计构件取得，`triggered` 另查真实重叠或求时器触发事件；检查点已到达可能仍被提前冲线截断，不能当作三个面板都可操作。

这批样本中，火箭＋省流取得/触发为 2/2，黄毛＋跑马灯为 5/3，改装＋火箭为 3/2；亢奋＋狂暴为 4/0，起飞＋纸飞机为 1/0，风火轮＋翻新为 0/0。三张限制下，取得两张牌仍须判断剩余期限与后续窗口，第三张需要补足当前局势；这些样本不能证明各流派平衡或最优策略。随机选择的名次计数为 `[9,5,14,17,35]`，版本答案触发 0 次，也不能直接外推返奖分布。

## 8. 卡牌清单

### 8.1 卡牌数据结构

```ts
interface CardView {                 // src/race/cards/types.ts：卡面，求时器不读取
  cardId: string
  quality: 'common' | 'rare'       // 取自规则表 rare，即强效果子集，参与牌堆末两张保底
  name: { zh: string; en: string }
  desc: { zh: string; en: string }  // 由规则表生成，必须写明代价，尤其是自动触发条件与真实代价
  meme: string                      // 梗源，用于卡面美术方向与图鉴
  art: { icon: string; tint?: number }
  cpuUsable: boolean                // 取自规则表 cpu：电脑马私有牌堆是否允许取到
}
```

卡面由三处各管一块：规则数值与资格在 `src/race/paid/cardRules.ts`（`PaidCardRule`），名称、梗源与图标在 `src/race/cards/metadata.ts`，说明文字由 `src/race/cards/paidCards.ts` 按规则表生成。`src/race/cards/pool.ts` 的 `CardDef`（带 `effects`、`stack`）只保存 C-01 至 C-21 的声明式效果状态，供开发特效验收入口生成演示快照，求时器不读取。

牌堆是对整副卡池的一次无放回定序，**没有「这张卡只在第几个检查点出现」这种字段**——牌堆在开局就已定序，无从知道某张牌会落在哪个检查点。

每张卡的规则表项必须显式填写 `cpu`。电脑马只从 `cpu: true` 的卡中派生私有牌堆；只对玩家选牌界面有意义的卡标为 `false`，不以“抽到后空过”掩盖作用域错误。

`cpu` 为 `false` 的共 10 张：C-03、C-04、C-05（改变玩家发牌规则）、C-09、C-11、C-19、C-20、C-21、C-29【跑马灯】与 C-39【躺平是种智慧】，其余为 `true`；C-29 依赖玩家专用染色牌，C-39 依赖主动放弃。该范围已写入规则表并生成运行时 CPU mask。

有奖卡牌参数统一进入 `src/race/paid/cardRules.ts`，从该表生成 Solidity 与一致性向量；卡面从同一表读取数值。新机制只加入实际需要的门控、事件和参数；通用复制、主功能分类、候选保留和刷新额度加成不在现有规则内。

C-04 的附加 +20% 速度只在获得卡时生成一次独立实例，不因阶段、装备或死亡反应重复附加。复合卡的主效果时长明确为：C-23 的完整 24 秒阶段；C-24 的 20 秒监听；C-31/C-37/C-39/C-40 的永久监听；C-38 的 50 秒监听。C-30 跟随实际 15/10 秒速度分支；C-32 有装备时为瞬时刷新，按瞬时卡默认 20 秒，无装备时跟随 5 秒速度。其余新卡跟随卡表的有限效果时长。监听提前消费不撤销或延长这份独立加速。

每场五马至多各取得三张牌。按每张牌最多三个主体/奖励实例计 45 个，再加最多 20 个炸弹与五次 C-02 实际死亡产生的重生实例 25 个，以及改装监听的最多 10 个装备获得奖励实例（含取得时已有装备的触发），保守合计 80 个，低于求时器 96 个实例容量。这里的装备获得数量来自三张牌限制，不是给改装监听设置两次触发上限；周期爆发直接修改已有实例，翻新后按保留相位继续调度。

求时器以内联热核心与冷路径领域库组织，只部署单个 `PaidRaceSolver`；runtime 为 35,144 B，体积按 Monad 上限验收。重力井 RK2 步长为 250 ms，与前端轨迹共用生成参数并纳入规则哈希。80 场固定生产输入在 Monad 只读探针的平均/最大 solve gas 为 2.420M/3.854M，完整结果与本地逐场一致。严格最坏合法输入仍未认证：150 秒单井有效期投影为 600 步，积分部分消耗 5,827,799 Foundry gas；这不是已证明可达的整场输入。

## 9. 美术与资源需求

装备要挂在马的不同部位，这项需求直接决定渲染层的结构，不能等美术交付时再补。

### 9.1 骨架插槽

马匹 rig 定义一组稳定命名的插槽，规则内核不认识它们，只有渲染层使用：

| 插槽 | 位置 | 当前使用者 |
| --- | --- | --- |
| `torso` | 腹部中心，随马体根节点升降 | 火箭喷射器、史瓦西黑洞 |
| `head` | 头顶（相对马体图的固定比例点） | 黄毛、染成绿的的头顶尖发 |
| `hoof_fl` `hoof_fr` `hoof_bl` `hoof_br` | 四蹄 | 风火轮（四件） |
| `tail` | 尾根 | 彩虹拖尾发射点 |
| `body_center` | 身体中心 | 旋转突进的旋转轴心与拖尾分镜中心 |
| `aura` | 整体包围 | 设计预留，当前无使用者（重生闪烁直接作用于根节点透明度） |

插槽锚点取自马体图的固定比例点，随马体根节点升降。**【起飞】的 y 偏移作用于 rig 根节点**，全部挂载物自动跟随，不需要逐件处理。

### 9.2 每件装备的资源清单

一件装备的资源设计上不止一张图；当前每件装备是一张 16 帧循环分镜，渲染层级与朝向由 `RaceScene` 硬编码，没有装卸动画：

| 资源 | 说明 | 缺失时的降级（设计目标） |
| --- | --- | --- |
| 静态图 | 挂载态基础帧 | 占位色块 |
| 循环动画 | 挂载期间的 idle 循环（喷焰、吸积盘、火轮旋转） | 退化为静态图 |
| 装卸动画 | attach-in / detach-out | 直接出现/消失 |
| 渲染层级 | `behind_horse` / `on_horse` / `front_horse` | 默认 `on_horse` |
| 朝向处理 | 是否随马匹朝向翻转 | 默认翻转 |
| 卡面图标 | 选牌、HUD 生效槽、结算回顾三处共用（[架构 §8](architecture/overall.md)） | 占位图标 |

**资源与规则解耦。** 规则内核不 import 任何资源清单，这是把美术进度与玩法调参解耦的唯一方式——否则数值调不了，因为图还没画。资源加载失败时由加载页或分级门显示失败项并提供重试，不进入缺图页面；逐件降级（占位色块、退化为静态图）是设计目标。

### 9.3 拖尾类效果

彩虹拖尾与旋转突进拖尾都是循环分镜，不使用历史位置队列：彩虹带挂在尾根锚点，旋转突进带居中于 `body_center`。帧循环完全属于表现层，**不进求时计算、不进结算记录**；减少动态效果时停在首帧。

【交换】会让两匹马的 `laneIndex` 与渲染行瞬间互换，† 拖尾分镜随所属马匹出现在新行，不做跨行插值——插值会画出一条横跨赛道的彩虹，那不是交换该有的读法。
