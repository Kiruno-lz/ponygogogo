## 3. 架构边界

共同求时规则保留在 src/race，链交互在 src/chain，Phaser 表现在 src/game，卡面和结算分别保持 src/cards、src/result。继续复用现有规则表、RaceScreenDriver、Card、StageDialog 和 collectibleView，不复制一套试玩/有奖/验收实现。

UI 根目录保留 i18n.ts 与样式入口；页面、专用 Hook 和同场景测试按 shared/home/wallet/select/race/collection/settings/loading/showcase 聚合。共享类型不再从具体页面反向导入；样式拆分保持加载顺序与原画锚点。

每次改动保持端到端可工作。缺陷先进入测试并确认红线，再修复至全绿；纯移动使用现有行为测试和构建验证。合约大小与既有 Monad 计算成本检查不在本次重复执行。

## 4. 发布与清理

只保留本次采用的链上地址、规则哈希、索引器提交和端点。旧测试部署不再作为兼容目标或交付记录。链上不可删除的字节码无需继续在项目中留存引用。

正式 Cloudflare Worker 使用现有 ponygo 服务，保持 ponygo.kiruno.cc 与 WebAuthn rpId；preview 使用 ponygogogo-preview。发布入口显式选择环境，先清理/迁移 D1 再发布对应 Worker。不得将“数据库存在”记为生产图鉴已经交付。

索引器只处理当前 Game/Vault/Rewards 的事件；公开历史查询必须支持 roster 与获得物信息。余额、会话状态、返奖始终从 RPC/合约读取。
