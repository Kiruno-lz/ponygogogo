# 当前数值与复算

本文说明当前生产规则的数值来源与分析入口。规则数值以 TS 规范表及生成的 Solidity 表为准；统计产物只代表生成时的规则、输入与策略，不沿用旧规则下的胜率、返还率或 gas。

## 1. 运动与体力基线

### 1.1 当前生产参数

生产输入携带五名角色的 `roster`，`solver.ts/createState` 按 `PLAYER_BALANCE` 初始化玩家与 CPU。低层求时器仍接受不带名单的测试输入，其默认体力容量 1000、消耗 24/s 等参数不用于正常生产入场。

| 参数 | 当前值 |
| --- | --- |
| 赛道 / 里程检查点 | 100000 / 25000、50000、75000 |
| 起速 / 常规加速度 | 300 / 150 |
| 玩家运动基础上限 | 1800，角色能力另加上限修正 |
| 初始体力 / 容量 | 玩家与 CPU 均为 300；玩家奶龙为 400，CPU 奶龙没有容量加成 |
| 常规消耗 / 恢复 | 20/s / 10/s，分别应用消耗与恢复修正 |
| 超容量期间 | 消耗减半，恢复为 0，玩家与 CPU 相同 |
| 力竭期间 | 消耗为 0、恢复基线 15/s、加速度 0、运动基础速度钳至 1200 |
| 力竭退出 | 体力达到 135；当刻速度保持不变，再以加速度 150 恢复至自身上限 |
| 死亡 | 运动基础速度归零，以 150 恢复；位置、里程、B/K 和卡牌期限保留 |
| 重生免疫 | 5000 ms |
| 求时上限 | 600000 ms 模拟时间；未冲线马用 600001 ms 排序 |

时间消耗与恢复都按模拟时间计算，选牌慢放同时影响两者。即时补给允许超过容量；持续恢复钳至容量。亢奋使体力不低于 1；来劲在 30 秒监听内首次将进入力竭时补给 250 并拦截一次。

### 1.2 速度与资源公式

```text
b_motion = min(C, b_start + a_eff × Δτ)
b = b_motion + B
v = max(0, b × max(0, 1 + ΣP) + K)
cost = 20 × max(0.05, 1 + ΣcostDelta)
regen = (力竭 ? 15 : 10) × (1 + ΣregenBonus)
```

`B` 是参与百分比乘法的固定速度，`K` 是乘法之后的额外速度。死亡不清除二者；贡献在来源到期或移除时结束。常规净体力变化是 `regen − cost`；超容量只消耗，力竭只恢复。公式采用可读单位，实际整数舍入、阈值定位和单位转换见 `paid/motion.ts`、`paid/resources.ts` 与 `PaidRaceMotion.sol`。

### 1.3 电脑马难度与返还率

电脑马采用同一运动与体力基线，仅运动基础速度上限额外加独立整数偏移：

```text
C_cpu = 1800 + 100 + H(seed, openAnchor, 0, "horse.cap", group) mod 401
```

`group` 按非玩家槽位升序编号 0–3；`openAnchor` 是开场交易所在块的哈希。角色上限和消耗能力在初始化时另行叠加。下注档位不改变偏移区间或牌堆规则，0 MON 试玩用本地锚按同法派生。

合约总返还倍率为 `[3, 1.5, 1, 0, 0]`，含本金。`calibrate-cpu-difficulty.ts` 评估随机、短视和前瞻三种策略；前瞻只对部分随机卡平均三份预测锚，并在进程内给对手注册无能力实验角色。该名单不属于九角色生产目录，结果不能作为全部合法名单或任意策略的收益上界，不能声称当前规则保证 RTP < 1。

## 2. 角色能力

名称与模板见 `src/ui/i18n.ts`，数值见 `ponyRules.ts`。玩家与 CPU 都按名单取得能力；初始刷新仅用于玩家，奶龙容量加成也仅用于玩家。

| ponyId / 角色 | 当前能力 |
| --- | --- |
| 0 Kiruno | 每次获得稀有卡附加 +4% 速度，期限按卡牌主效果及附加规则确定 |
| 1 Shadow | 玩家开局 +1 次刷新 |
| 2 Berry | 直接获得装备时期限 ×1.5；持有任一装备期间速度 +10%，不按装备件数叠加；偷取与翻新按各自期限规则处理 |
| 3 Cloud | 首次获得每种卡牌主功能，附加 +3% 速度 20s |
| 4 Thunder | 起飞时速度 +25% |
| 5 牛来 | 运动基础上限 +100，体力消耗 +10% |
| 6 啥马 | 玩家主动放弃选牌时速度 +16% 20s，超时不触发 |
| 7 奶龙 | 玩家容量 +100；补给类卡实际增加体力时追加 50 |
| 8 咕咕嘎嘎 | 重复获得同一主功能时速度 +12% 20s |

装备偷取继承来源剩余时长；翻新取原始完整时长，不重新应用长情倍率。能力触发、期限与日志以 `solver.ts/onPonyCard`、`ponyFood` 及生成的 Solidity 实现为准。

## 3. 卡牌与计算边界

40 张卡的当前参数、品质、CPU 资格与交互见[卡牌设计](../card-design.md)，唯一数据源是 `cardRules.ts`。重力井 20s、全场反比衰减，半强度距离 8000；风为 ±25%；跑马灯一种毛色恢复 +150%，两种另加速度 +200%。动态场使用最长 250 ms 的定点 RK2，步长纳入规则哈希。

受控单卡、强制组合与自然派生对局分别报告。单卡标称百分比不能直接当成全程收益；装备被移除、死亡、力竭、条件门控、实际覆盖时间和提前冲线都会改变结果。有限样本的最佳观察名单不是理论最优名单。

## 4. 复算与验证入口

| 入口 | 用途与输出 |
| --- | --- |
| `scripts/analyze-numerical-balance.ts --out <目录>` | 生产求时器的受控单卡、组合、刷新与进程内候选参数比较；输出 simulation.json、optimization.json 与 TSV |
| `scripts/analyze-paid-card-builds.ts` | 构件取得、门控、覆盖与真实派生构筑；统计口径由脚本参数决定 |
| `scripts/analyze-pony-balance.ts`、`pony-balance-planner.ts` | 角色配对与策略比较，包含进程内无能力对照角色 |
| `scripts/analyze-pony-strategies.ts` | 完整名单枚举与固定策略比较，复现见[策略研究](../_reaserch/pony-strategy-validation.md) |
| `scripts/calibrate-cpu-difficulty.ts` | 对偏移区间采样，结果保存为 JSONL；`--summary` 汇总指定目录 |
| `scripts/measure-paid-solver.ts` | 在 Monad 用只读 state override 比较 80 场生产输入的结果与 gas，不能替代真实交易验收 |

```bash
bun run check:paid-cards
bun run check:paid-vectors
bun run check:pony-rules
bun run check:reward-rules
bun run check:pony-vectors
bun test src/race
forge test
bun run check:contracts
bun run check:solver-monad
```

生成物检查只证明表和向量与当前源码相符；运行测试才验证行为。Foundry gas 是本地计价回归数据，Monad 探针是有限生产样本，不等于最坏合法输入上界。统计变更后记录规则哈希、样本种子、名单、策略、实际取得卡牌和完整输入，禁止复制旧规则的通过数量或收益排名。

## 5. 尚未接入的数值目标

以下是保留的设计目标，不是当前生产行为或已经测得的收益：

- 距离消耗目标为每 1000 实际移动距离消耗 11.5 体力，超容量时减半；恢复仍按模拟时间。当前位置交换不计里程。
- 三张卡合计的多场平均目标：全体力构筑有效体力收益 300、全程等效加速 5%；全速度构筑有效体力收益 0、全程等效加速 25%。角色能力单独统计。
