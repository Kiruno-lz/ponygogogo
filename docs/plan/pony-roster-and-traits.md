# 小马角色、获得与选马

本计划定义角色目录、稀有卡与角色的获得和存储、选马队列、开赛名单协议、初始能力与美术规格。单场仍为五名参赛者。

## 1. 规则总览

1. Kiruno、Shadow、Berry、Cloud、Thunder 默认开放；牛来、啥马、奶龙、咕咕嘎嘎须获得。
2. 稀有卡与非默认角色共用一条获得流程：有奖场次在结算交易内以区块哈希为种子抽取，获得记录上链，客户端再并入同一份加密收藏文档。
3. 合约与求时器接受目录内任意角色，不校验解锁。解锁只决定客户端选马队列与图鉴展示，属于收集进度；获得物不影响返奖、名次与入场资格。
4. 开赛时，选马页屏内五匹即为参赛者，各自从所站赛道起跑；名单与赛道作为合约入场与求时器输入。
5. 每匹角色带一个初始能力，参数与卡牌规则同法从 TS 规范表生成 Solidity。

## 3. 身份、名单与赛道

### 3.1 三个字段

| 字段 | 含义 | 生命周期 |
| --- | --- | --- |
| `ponyId` | 角色目录身份：Kiruno 0、Shadow 1、Berry 2、Cloud 3、Thunder 4、牛来 5、啥马 6、奶龙 7、咕咕嘎嘎 8 | 永不改变 |
| `raceHorseId` | 单场参赛索引 0–4，等于开赛赛道；事件、目标、排名与结果数组按此索引 | 开赛至结束固定 |
| `laneIndex` | 当前赛道 0–4，0 为屏幕最下方的 1 号赛道 | 开赛时等于 `raceHorseId`，赛中可被交换类规则改变 |

`roster[raceHorseId] = ponyId`。交换赛道与毛色变化不交换角色或能力；跨马卡牌目标仍按 `raceHorseId`。

### 3.2 开赛名单

点击开赛时读取选马页窗口：屏内位置 `k`（自上而下 0–4）的角色站在 `laneIndex = 4 − k`，即 `roster[4 − k] = orderedPonyIds[windowStart + k]`；`playerHorseId` 为已选角色所在的 `laneIndex`。屏外角色不参赛。

名单由玩家通过滚动决定，包括对手角色及其能力。CPU 的基础速度、加速度、上限与牌组仍由 seed、开场锚与档位按非玩家槽位顺序派生，与现行规则一致。能力平衡必须对玩家可挑选的最有利对手组合成立（§6.4）。

### 3.3 协议输入

- 入场新增 `uint8[5] roster`。合约校验：五项互不相同、均为目录内已启用角色、`playerHorseId ∈ 0..4`；不校验解锁。
- `SessionOpened`、session view、`IPaidRaceSolver.RaceInput`、浏览器 ABI、Agent 入场、`scripts/keeper.ts`、向量编码、Envio schema 与 handler 同步增加 `roster`。旧 Game 的场次按 `[0,1,2,3,4]` 解码，不把旧 `horseId` 字段就地换义。
- 能力参数、启用目录与卡牌主功能分类进入规则哈希；`roster` 是场次输入，随事件公开。立绘与动作图不进入结算。
- 免费试玩用同一输入结构在本地求解，不发交易。

## 4. 选马队列与输入

### 4.1 屏幕坐标与队列

```ts
type PonySelection = {
  orderedPonyIds: readonly number[] // 进入场景时洗牌一次
  windowStart: number               // 0..max(0, N - 5)
  selectedPonyId: number | null
}
```

- 进入场景时以默认开放角色与已获得角色组成集合，去重后用无偏 Fisher–Yates 洗牌一次；测试注入确定性 RNG。洗牌只服务展示，不进入链上随机。
- 屏内位置 `k`（自上而下 0–4）显示 `orderedPonyIds[windowStart + k]`，站在 `laneIndex 4 − k`。队列首位在最上方的 5 号赛道，向下延伸；`windowStart + 5` 起的角色在 1 号赛道下方屏外，`windowStart` 之前的角色在 5 号赛道上方屏外。
- 赛道旗帜与赛道坐标属于赛道层，固定不动；角色横向偏移按所在 `laneIndex` 取（现有 `[86, 107, 123, 130, 144]`），不按角色 ID。
- 只有真正进入场景才洗牌；切换语言、档位、余额刷新、弹窗开合都不重排。场景内收藏进度更新时保留相对顺序，新获得角色加到队尾，并钳制窗口。

### 4.2 箭头与直接点马

上箭头位于 5 号赛道上方，下箭头位于 1 号赛道下方，始终占位。

| 输入 | 条件 | 窗口 | 选中 ID | 动画 |
| --- | --- | --- | --- | --- |
| 点上箭头 | `windowStart < N − 5` | `+1`：整列上移一位，最上方角色移出，下一位从下方进入 1 号赛道 | 不变 | 角色与金圈一起上移 |
| 点下箭头 | `windowStart > 0` | `−1`：整列下移一位 | 不变 | 角色与金圈一起下移 |
| 点不可用箭头 | 无相邻角色 | 不变 | 不变 | 无；按钮为 disabled |
| 直接点马 | 屏内 | 不变 | 点中的角色 | 金圈直接出现在该角色脚下，无移动动画 |

示例：队列 1–6 号起点显示 1–5 号（1 号在 5 号赛道）。点上箭头后显示 2–6 号，6 号进入 1 号赛道；在起点点下箭头无变化。只有五匹时两箭头均禁用，不循环、不回弹。屏幕阅读器名称为“队列上移”“队列下移”。

当已选角色处于边缘，箭头的动作会使已选角色移出屏外的情况：金圈不进行动画，选择的角色变更为相邻没有被移出的角色，左上名牌与能力说明显示为新选择的角色。

### 4.3 方向键

方向键按屏幕方向移动选中位置：↑ 选屏幕上方相邻角色（赛道号 +1），↓ 选下方相邻角色（赛道号 −1）。

| 状态与输入 | 选中 | 队列 | 金圈 |
| --- | --- | --- | --- |
| 未选择，首次 ↑ 或 ↓ | 屏内位置 2（3 号赛道）的角色 | 不动 | 直接出现，无移动 |
| 已选位置 1–4，按 ↑ | 上方相邻角色 | 不动 | 单独上移一格 |
| 已选位置 0–3，按 ↓ | 下方相邻角色 | 不动 | 单独下移一格 |
| 已选 1 号赛道（位置 4），按 ↓，队列有下一位 | 队列下一位 | `windowStart + 1`，整列上移 | 停在 1 号赛道 |
| 已选 5 号赛道（位置 0），按 ↑，队列有上一位 | 队列上一位 | `windowStart − 1`，整列下移 | 停在 5 号赛道 |
| 已选队列首位按 ↑，或末位按 ↓ | 不变 | 不动 | 无 |
| 已选角色在屏外，按 ↑ 或 ↓ | 队列相邻角色（↓ 为下一位，↑ 为上一位）；无相邻时保持原选中 | 最小移动使目标可见 | 随目标就位 |

键盘只在选马场景且无弹窗时生效；焦点在下注筹码等自带键盘行为的控件上时不截获。已处理的方向键阻止页面滚动。角色列使用单一 roving tab stop，焦点跟随选中角色；Enter/Space 选择聚焦角色。

### 4.4 动画与输入排队

- 队列移动与金圈移动均为 500 ms、ease-out 的 CSS transform；X/Y 按目标赛道坐标同时计算。
- 角色 DOM 以 `ponyId` 为 key，移动时不重新挂载、不重置 idle 帧；只渲染屏内五项及上下各一个过渡项，角色列局部裁切，屏外项不可点击、不可聚焦。
- 金圈是单个独立对象，深度低于全部角色：箭头滚动时随已选角色移动，键盘边缘滚动时保持坐标，直接点马时立即定位。
- 动画进行中收到的箭头、方向键与点马输入只保留最后一次，当前动画结束后执行；长按产生的 repeat 同样覆盖等待项。返回、退出登录或开赛时清空等待项并取消过渡，迟到的 `transitionend` 不写回状态。
- `reducedMotion` 下直接到达终态，不排队。

## 5. 获得与存储

### 5.1 获得物与获得机会

- 可获得物：`cardRules.ts` 中 `rare: true` 的卡牌，以及非默认开放角色。普通卡与初始五匹默认拥有。稀有标记调整后，已获得记录按 cardId 保留，不回收。
- 每个经 `settleSession` 正常结算的有奖场次抽取一次，与名次、档位、返奖无关。判负（`forfeitSession`）不抽取；免费试玩没有链上结算，不产生获得。

### 5.2 结算交易内抽取

新增两部分：

- `contracts/PonyRewards.sol`：持久账本，跨 Game 版本存续。`ownedMask(player)` 以位图保存已获得物（卡牌位 = cardId，角色位 = 64 + ponyId）；`record(sessionId, player, assetKind, assetId)` 只接受 owner 登记的 Game 调用，拒绝重复 sessionId 与已拥有项，并发出 `CollectibleGranted(bytes32 indexed sessionId, address indexed player, uint8 assetKind, uint8 assetId)`，`assetKind` 0 为稀有卡、1 为角色。
- 抽取库：由 `src/race/paid/rewardRules.ts` 生成，编入 Game。`PonyGame.settleSession()` 完成求时、名次校验与会话状态更新后，在同一交易内执行下列抽取，再由 Vault 直接返还；获得物先于玩家收款调用，避免玩家的 `receive()` 消耗 gas 后使奖励守卫回滚有效结算：

```text
seed  = keccak256(abi.encode(blockhash(block.number − 1), block.chainid, game, sessionId, player))
roll  = uint256(keccak256(abi.encode(seed, 0))) % 10000
roll ≥ grantChanceBps → 无获得
候选  = 规范顺序（稀有卡按 cardId 升序，其后角色按 ponyId 升序）中 ownedMask(player) 未拥有的可获得物
W     = Σ 候选权重；W = 0 → 无获得
pick  = uint256(keccak256(abi.encode(seed, 1))) % W，按规范顺序累减权重选出一项，调用 record
```

- EVM 中 `blockhash(block.number)` 恒为 0；“结算时的区块哈希”取结算交易所在区块的父区块哈希，即该交易内可读的最新区块哈希。
- 初始参数：`grantChanceBps = 2000`，稀有卡权重 1，角色权重 3。调参只改 `rewardRules.ts` 并随新 Game 版本生效。
- 抽取不读写求时器状态，不进入 Solver/Support。账本调用不得阻断返奖：`settleSession` 入口要求剩余 gas 不低于固定的奖励预留，再以固定 gas 调用 `record`；调用失败时发出 `CollectibleSkipped(sessionId)`，并继续完成结算。
- 结算可由任何地址在结算窗口内发出。发送方能选择发送时机，也能用合约在抽取不利时回滚、在下一区块重试，从而重抽。获得物不影响返奖与入场，这一偏差只影响收集速度；该随机数禁止用于返奖、名次或任何有经济价值的结果。

### 5.3 收藏存储

- 链上 `PonyRewards` 是获得的权威记录；加密收藏文档是该通行密钥身份的个人收藏副本。卡牌与角色同构，按同一流程处理。
- 沿用现有 PRF 用途隔离、AES-256-GCM、Ed25519 同步身份、一次性挑战与 `expectedVersion` 条件写；envelope 与 AAD 保持 v1，解密后的明文升级为：

```ts
type CollectionProgress = {
  schemaVersion: 2
  rareCardIds: string[]
  unlockedPonyIds: number[] // 只存非默认角色
}
```

- 旧 v1 稀有数组读为 `{ schemaVersion: 2, rareCardIds: oldIds, unlockedPonyIds: [] }`，读取不触发覆写，首次合并新获得时写 v2。不改 PRF salt、rpId 或同步签名域。
- 解密后严格校验：去重、稳定排序，卡牌与角色分别对照规范目录。未知 schema、未知 ID、解密失败都不重置、不覆写原密文。旧客户端遇到 v2 明文时报错并提示更新，不得写回只含卡牌的数组。
- 写入时机：结算回执含 `CollectibleGranted` 时合并该项；每次解密收藏后读取当前游戏账户的 `ownedMask`，与文档求并集，有新增则条件写。断线、重复拉取战绩或刷新页面不会重复获得，漏写在下次解密时补齐。
- 收到 409 时重新读取解密，按集合并集合并，以新版本有限重试。账号切换或退出时立即作废旧请求，清空明文与密钥。
- 选马与图鉴的开放集合 = 默认开放 ∪ 链上 `ownedMask` ∪ 已解密文档。两者都未读取时只开放初始五匹，图鉴显示“进度未读取”，不显示为未获得。

### 5.4 结算悬浮窗与海报

- 悬浮窗：`usePaidRace` 从结算回执（或已结算场次的日志）解析出 `CollectibleGranted` 时，在结果页上方弹出独立悬浮窗，展示卡面或角色立绘、名称、类型（稀有卡 / 小马）与“已加入图鉴”。关闭按钮与 Escape 关闭，焦点限制在窗内，关闭后回到结果页原焦点。结果页先于结算出现，悬浮窗在结算确认时弹出；无获得、判负与试玩不弹出。同一 sessionId 在一个结果页实例内只弹一次。
- 海报：`posterContent` 增加可选 `grant`。场次有获得时，`drawPoster` 在 1620×971 画布上绘制固定的获得物窗口（卡面或角色立绘加名称），与马、奖牌、二维码互不遮挡；无获得时保持现有版式。分享对话框打开期间结算确认的，海报按新事实重新生成。

## 6. 初始能力

### 6.1 规则语义

- 能力从比赛初始化起存在，不占选牌名额、14 张牌堆或装备槽；CPU 按 `roster` 同样持有能力。触发写入事件日志与 trace，UI 只展示规则结果。
- “获得卡牌”指实际生效的有效选牌：手动选择、有效自动选择与 CPU 获取。展示、刷新候选、主动放弃、超时、非法交易、被断卡阻止的面板、装备偷取与续期都不算获得。获得历史按参赛者独立记录，不因效果到期、死亡、装备丢失或毛色改变而消失。
- 百分比速度进入 `P_i` 加算和，消耗修正进入 `ΣcostDeltaBps`，不改基础加速度 `a_i`。时长按模拟时间 `τ` 计，选牌慢放时同步慢放。能力不修改 gogo、镜头、随机锚、档位或赔付。
- 数值以 `src/race/paid/ponyRules.ts` 为唯一来源；平衡阶段只改该表并升级规则版本。

### 6.2 角色能力

| 角色 | 默认开放 | 能力 | 构筑倾向 |
| --- | --- | --- | --- |
| Kiruno | 是 | 稀有专精：实际获得稀有卡时，追加一个 +10% 速度的 `bonus` 速度实例；时长由 `bonusDurationMs` 决定（跟随该卡主效果时长，瞬时卡 20 秒，永久卡永久，C-13 跟随窃得装备时长）。与 C-04 的 +20% 各自独立加算 | 稀有优先，刷新找稀有 |
| Shadow | 是 | 轻装：躯干、尾部、脚部均无装备时 +8% 速度，有任一装备时为 0 | 无装备速度、补给、干扰 |
| Berry | 是 | 长情：从有效选牌获得的装备初始持续时间 +20%，按整数 ms 向下取整；偷来的装备与续期不放大，转移后保留既定到期时间 | 装备覆盖路程 |
| Cloud | 是 | 百花齐放：本场首次获得某一主功能类型时，创建独立的 +7% 速度、20s 效果；同类后续获得不触发、不续期 | 不同主功能混搭 |
| Thunder | 是 | 乘风：处于起飞状态时 +8% 速度；多个起飞来源不叠加，最后一个来源到期时移除 | 起飞门控 |
| 牛来 | 否 | 有牛劲：初始化时基础上限 `C_i += 100`；持续消耗修正 +2000 bps，恢复与容量不变 | 节流、补给支撑高上限 |
| 啥马 | 否 | 随便跑跑：主动放弃检查点时 +12% 速度 20 秒，每个检查点至多一次；超时、非法选择与断卡不触发，可与 C-39 并存 | 主动放弃的取舍 |
| 奶龙 | 否 | 大吃货：有效获得补给卡且该卡在获得时真实增加体力，额外普通恢复 50 体力；周期恢复不触发，不产生 overcap，不递归触发 | 即时补给 |
| 咕咕嘎嘎 | 否 | 重复节奏：有效获得的卡与此前任一已获得卡同主功能时 +12% 速度 20 秒，每次获得至多一次，各次独立计时 | 同类专精 |

### 6.4 策略验证

- 使用真实 `derivePaidDeck` 候选、合法刷新与规范选择时间，不人为保证发到偏好牌。先用定向场景证明偏好能改变选择，再用固定调参集与独立留出集检查可达性。
- 覆盖：稀有弱即时收益与普通兼容牌的取舍；同类专精与异类混搭；牛来在补给/节流与直接加速之间；装备时长与剩余路程；主动放弃与超时。
- 名单由玩家挑选：对每个玩家角色，枚举对手组合与赛道排列，以最有利组合下的玩家胜率与期望返还作为平衡上限。
- 记录实际获得、能力触发次数、覆盖时间、体力收支、五马冲线时间与原始/结算名次；无卡、偏好卡未出现、受击死亡与临近冲线单独记录。

验证入口为 `scripts/analyze-pony-strategies.ts` 与 `tests/api/ts/pony-strategy.test.ts`；每个角色、每个种子完整枚举 `C(8,4) × 4! × 5 = 8400` 份名单。定向牌面与随机派生结果分开，样本最有利名单不宣称为未采样随机锚及所有策略的理论上限。方法与证据见[初始能力与选阵容策略验证](../_reaserch/pony-strategy-validation.md)。
