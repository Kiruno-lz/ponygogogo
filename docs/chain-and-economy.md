# 链上与经济

## 1. 权威结果

有奖比赛由 Monad 上的 PonyGame 和 PaidRaceSolver 按开场冻结的输入复算；PonyVault 只执行 PonyGame 的账务指令。浏览器名次是预览，不能决定奖金；Envio 只提供可回滚的历史与统计。现行架构决策见[项目决策](decision.md)，合约与账户边界见[链上架构](architecture/onchain.md)。

## 2. 会话与随机输入

开场绑定 `sessionId`、玩家智能账户、选中马、下注档位、赔率、规则版本、seed 与入场区块。seed 与入场区块哈希固定初始牌堆和基础参数。每笔实际选牌交易记录检查点、刷新/选牌输入、入块秒 `Ti` 与区块号 `b_i`；在后续区块验证并封存 `blockhash(b_i)`，供该卡随机效果派生使用。

自动选牌、超时、放弃、断卡和未到达检查点按规则分别处理，不生成客户端可指定的随机源。随机锚不能由客户端补报；超过链上读取窗口的会话按协议判负。

比赛时钟由 `T0` 和实际选择交易的秒级 `Ti` 重建，不从区块高度或浏览器本地时间推导。浏览器用高精度时钟绘制预览；交易确认后按链上规范时间校正。选择时间只证明秒级链上顺序，不声称证明鼠标点击的毫秒时刻。

## 3. 结算与排名

`settleSession(sessionId)` 不接收浏览器名次、冲线时间或终态作为付款依据。求时器计算五匹马的首次冲线时间，按 `(finishTime, horseId)` 得到物理排序 `rawRank`；合约再验证【版本答案】，得到结算排序 `settlementRank`。赔率按 `settlementRank` 计算。

无重力井区间使用事件边界上的解析积分；重力井按实时距离改变五马速度，采用规则版本冻结的定点数值积分与事件定位。链上不按浏览器帧或 50Hz tick 回放比赛。无效已存选择按该检查点无交易处理，不得使求时器回退。

## 4. Vault 与偿付

游戏只使用 Monad 原生 MON，不使用 ERC-20 或 WMON。下注、用户充值和庄家注资通过 payable 调用转入 Vault，余额以 wei 记账。

定义 `A` 为玩家可用余额总和、`L` 为锁定下注总和、`H` 为庄家流动性、`R` 为未结算最大净赔付预留：

```text
address(Vault).balance >= A + L + H
H >= R
R(session) = max(maxPayout - stake, 0)
```

开场时锁定下注并预留最大净赔付。结算后将实际返还记入玩家余额，判负则按返还 0 结算；两种状态互斥。庄家只能提取 `H - R`。用户充值、提款和管理员操作不得改写已开场赔率或规则。

Vault 不设退款。随机锚过期导致会话无法结算、求时器故障会话被判负或玩家放弃结算，都按返还 0 处理；不存在退款入口。

## 5. 当前测试规则

当前测试网档位为 `0 / 0.3 / 1 / 5 / 10 MON`，0 仅用于免费本地试玩。赔率总返还倍率（含本金）为 `[3, 1.5, 1, 0, 0]`；最大庄家净预留依次为 `0 / 0.6 / 2 / 10 / 20 MON`。

当前阶段正式上线范围仅为 Monad 测试网，创建账户自动领取 1 MON 测试币等机制仍保留，不涉及主网。返奖率与最坏 gas 验收安排在牌库补充、卡牌数值平衡和电脑马性格平衡完成后；这些不是当前测试网上线门槛，顺序见[项目决策](decision.md)。

## 6. 交易状态与恢复

界面区分交易已提交、已入块与最终确认；预览奖金不标记为已到账。响应超时或状态不确定时，客户端先按账户、`sessionId`、调用 ID、交易哈希与合约状态恢复，再决定是否重试。结算失败保留原会话及可复核输入，不创建新场覆盖旧记录。

资金和会话终态以 RPC/合约为准，不以浏览器缓存、调用提交成功或 Envio 索引进度代替。
