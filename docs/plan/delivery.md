# 敏捷交付与验收

## 1. 交付方式

首要目标是让游戏动起来、真正形成好玩。因此可玩性验证全部前置：A、B 两阶段在本地无链环境跑通完整比赛与手感调参，链上闭环排在其后。每一阶段都以可运行入口、可重复测试和实际演示验收；没有验收证据不标完成。A、B 两阶段已完成，第 2 节那条动线全程可玩；D 阶段的钱包那一半被提前取出来做完了（见该阶段行），合约仍未开始。

固定的长期边界是纯 TypeScript 规则内核、独立渲染、合约只管资金与记录。合约对玩法无知：不重放、不校验完成时间、不派生电脑马，因此不存在 Solidity 版规则内核，也不做规则的跨语言一致性向量。两端唯一需要给出相同结果的是发牌派生，而它只吃链上 seed；注意它是**有状态的十四次抽取**（无放回，第 k 张取决于前 k−1 张抽走了谁），不是一个无状态的下标函数，复算方必须按同一顺序走完十四次。验证方式是任何第三方用链上 seed 复算整副牌堆。A 阶段的规则内核是贯穿全部阶段的长期资产，不是需要丢弃的原型。

当前目标是测试网 demo：可行、可运行、有效果。名次以浏览器的运行状态为准，合约受理后按赔付表付款；校验能力以 `IResultValidator` 钩子预留，demo 期指向 `AlwaysAccept`。验收条目不得把任何一项写成防作弊能力。

产品形态只有链上比赛，下注可以为 0 MON。当前运行形态里钱包已真接 Monad 测试网，比赛的入场与结算仍是本地 mock，属于开发预览，不对外作为产品形态展示，也不显示任何 tx。

首页与结算页的美术已从占位切片换成作者定稿的无字素材，按原画版位重新校准；界面素材已齐，只剩 21 张卡面方形图标仍在用占位图，清单见[素材管线说明](../../scripts/README-assets.md)。

## 2. 阶段与完成条件

| 阶段 | 可交付结果 | 验收与进入下一阶段的条件 |
| --- | --- | --- |
| A：能跑起来的比赛 | 纯 TS 规则内核（固定种子、mock 时钟、可批量模拟）+ Vite + React + Phaser 渲染：固定五匹马（一名玩家 + 四匹橡皮筋 CPU）、跟随镜头、idle 起跑、快跑、体力、冲线名次；本地无链 | 关闭渲染层后同一 `(seed, 按 tick 对齐的输入序列)` 给出相同名次，证明渲染不参与规则；同一输入在 30/60/120fps 下终态逐字段相等；CPU 速度的计算路径不引用任何名次或目标完成时间（代码审查项）；狂点到力竭、卡准节拍匀速、慢而稳、完全不点均可完赛且名次关系符合直觉，且不存在单一最优策略（狂点与卡准的完成 tick 差距在 5% 以内、卡准与休息交替严格优于两者）；只改时机不改频率时完成 tick 随命中度单调改善且幅度可测；死亡后即使处于力竭也能靠 `aMax/2` 的保底加速度爬回 `vLow`；固定 seed 下改变输入能改变名次，名次不退化为常数；窄屏与移动横屏操作可用，五条赛道可读 |
| B：完整玩法与手感 | 14 张有序牌堆 + 游标发牌、里程检查点与刷新机制、效果模块骨架（速度 / 状态 / 装备 / 能力绑定 / 实体 / 场 / 发牌修正）、至少 14 张卡池（含强效果子集 ≥ 2，玩家的卡全部自作用）、慢放与超时、结算卡片、中英文、设置 | **手感指标是本阶段的核心门禁**：固定 seed 批量模拟下，最优玩法与放任不管的名次差期望落在 `[2, 3]`，名次差为 0 的样本比例低于 5%；牌堆十四张互不重复、末两张必为强效果卡，展示序列与 0–3 次选择及任意刷新组合都可回放一致；遍历 10000 个 seed 断言上述两条，另以静态断言检查总卡池 ≥ 14、强效果子集 ≥ 2（卡池不足是对所有 seed 成立的静态事实，遍历碰不出来）；全场 0.1 倍速、现实 20 秒到期、最后 5 秒提醒、隐藏按钮不能通过快捷键触发；一次 20 秒慢放最多前进 2 秒模拟距离，不越过下个检查点或终点；「落后追赶」的增益在不读取任何电脑马状态的前提下可复现；**里程与位置分离可验证**：反复交换 20 次后抽卡次数仍等于里程跨过的档位数，且提前冲线的场次抽卡次数少于三次而非报错；**效果模块可插拔可验证**：打乱模块注册顺序后终态逐字段不变，缺模块的卡在构建期失败，清空全部装备资源后同一输入序列的名次与编码逐字段相等 |
| C：薄合约 | Foundry 实现 `enterRace` / `settleRace`（主体约 60 行）、`IResultValidator` 与 `AlwaysAccept`、可配置赔付表、`rulesVersion` 随场记录；本地链跑通两笔交易 | 合约内没有任何玩法断言（代码审查项：不存在对完成时间、名次合法性或输入内容的比较）；validator 换成恒 false 实现后 `settleRace` 被拒、`enterRace` 不受影响、主合约地址与字节码不变，换回后同一场可结算；链上 seed 与 TS 发牌派生复算出的十四张牌逐张相等且两两不重复；`settleRace` 成功后槽位删除，重复结算 revert；任何 calldata 输入下单场赔付不超过赔付表上限，Vault 余额不为负 |
| D：测试网闭环 | ~~Mera 创建/恢复、余额~~（已完成）、真实两笔交易、Vault 偿付上限、Submitted / Included / Finalized 状态、从 calldata 取回比赛记录 | 钱包部分已验收：注册与登录落在同一地址、链上余额从 RPC 读出、助记词可导出并能导入标准钱包。余下部分要实际测试网交易证明：入场交易确认后 seed 可读、整副牌堆据此生成并起跑；赢家返还到账；最后两名 `G = 0` 仍成功提交 `settleRace` 并留下 event；任何第三方仅凭链上 seed 与结算 calldata 离线复算出发牌与完整比赛记录，与前端展示一致；广播失败重试不产生第二场比赛 |
| E：分享与收尾 | 结算海报与分享（卡面、出图、剪贴板、X、系统分享面板）、目标设备适配、资金不变量审查、正式部署配置 | 资金不变量测试全通过；设备矩阵通过（含四处分发路径实测）；结算延迟分位数测量完成。**赔付表取一组让手感成立的数即可，不做收益标定**——它是可配置项，改赔率不需要重新部署 |

合约薄到不构成架构风险：`settleRace` 只做一次校验器调用、一次赔付表查表和一次转账，gas 在数万量级，主要成本是 calldata 长度，不需要提前做 gas 证伪。唯一会反过来决定架构是否成立的外部依赖是 **Mera 的设备兼容性**，已在钱包接入时验证完往返，没有拖到 D 阶段。结论是它确实构成产品约束而非工程风险：账户完全由 WebAuthn 的 PRF 扩展决定，认证器不给 PRF 就没有账户，没有降级路径。桌面版 Chrome 只有存进 Google 密码管理器的通行密钥带 PRF，存在本地 profile 的会直接失败；1Password、iCloud 钥匙串、Windows 密码管理器与 YubiKey 5C Nano 已确认可用。因此界面必须把 `PRF_UNAVAILABLE` 单独成一类错误并给出改存位置的指引，不能混进「操作失败」。

结算 calldata 承载完整比赛记录而非只存哈希，长度直接决定 gas，编码与上限在 C 阶段定死。

探索用的验证代码在得出结论后删除；结论若影响架构，按第 4 节规则写回探索文档。

每阶段只拉入表中必要的依赖，按场景提交独立可回退的改动。测试网验收必须保留 chainId、合约地址、raceId、入场 tx、结算 tx、对应 `rulesVersion` 与离线复算摘要；本地 mock 不能代替这些证据。

## 3. 当前建议默认与定案事项

| 事项 | 当前采用的建议 | 定案方式 |
| --- | --- | --- |
| 参赛形式 | 固定五匹马：一名玩家 + 四匹 CPU；玩家起跑前可挑选其中一匹作为自己的马；不提供马数与难度选项 | 已定案；马由 `horseId` 标识、不绑定赛道，赛道只决定画在第几行；seed 派生四组性格参数按剩余 `horseId` 升序分配，选马只换外观不换对手 |
| 检查点触发 | 按每匹马自身跑过的里程，跨过 25% / 50% / 75% 各一次，一场最多三次；位置跳变不产生里程 | 已定案；里程与 `pos` 是两个独立量，跑满 100% 里程不等于冲线、没跑满也可以冲线。传送类卡牌因此不需要任何额外规则 |
| 慢放时钟 | 全场 0.1 倍模拟；20 秒现实时间 | B 阶段边界时间测试 |
| 点击手感 | 一个输入喂三条曲线：**频率**正比于加速度（速度在 `[vLow, vHigh]` 带内爬升）、**点击次数**决定体力消耗（每次固定一份）、**时机**决定体力恢复速度（目标间隔处最高，两侧下降，太快一侧更陡）。体力归零进入【力竭】（压到 `vLow`、锁按钮），恢复到 30% 才解除 | A 阶段实际试玩后冻结规则版本。**频率决定跑多快，时机决定能跑多久**，两个技巧分开可测；静态断言 `单次消耗 ÷ 目标间隔 > R0 × bHit`，保证完美节奏也不是永动机 |
| seed 的职责 | 唯一职责是固定一副 14 张的有序牌堆（互不重复，无放回定序，末两张为强效果卡），三个检查点按游标取牌、余量供刷新；使发牌可被事后验证为随机，不决定比赛结果 | 已定案；含义是运营方无法定向发牌，不等于对名次的任何保证 |
| 电脑马 | 实时橡皮筋 AI：每帧按与玩家的相对位置调速，seed 派生 `base/min/max/gain/slack/ease/amp/tau` 八个性格参数；抖动防贴身、高阻尼防速度突变、区间防跑飞；不预设成绩、不预设名次 | 已定案；**严禁以名次或目标完成时间作为速度依据**，出现即视为回到「先定结局再编演出」。抖动必须是 seed 与 tick 的确定性函数，用 `Math.random` 即失去可回放性 |
| 手感指标 | 同一场里最优玩法与放任不管的名次差期望 2–3 名；「怎么打都一样」的局低于 5% | B 阶段门禁；由固定 seed 批量模拟测量，是调橡皮筋参数达成的指标，不是公式输出 |
| 难度来源 | 下注金额调整橡皮筋强度与性格分布 | B 阶段与手感指标一起调参 |
| 名次判定 | 以浏览器的运行状态为准，冲线顺序即名次；合约受理不重算。**唯一例外是组合彩蛋【版本答案】**，它经由骨架的 `forcedRank` 把玩家置为第一 | 已定案；链上记录是可复核、不可阻止。彩蛋名次由三次选牌确定性推出，离线复算无需额外字段；但将来任何验算名次的校验器必须知道这条规则，否则会把合法彩蛋局判成作弊 |
| 合约职责 | 对玩法完全无知：收下注、派生并存 seed、接受浏览器报告的名次、按赔付表发钱、记录比赛 | 已定案；主合约内一行玩法断言都不能有，否则将来只能重新部署并迁移资金 |
| 校验钩子 | `IResultValidator`，只返回 bool，**刻意不声明为 `view`**；主合约只持有一个校验器地址，按 `rulesVersion` 分派由校验器自己内部完成；demo 期指向 `AlwaysAccept` | C 阶段实现并验证可替换性，含恶意校验器夹具 |
| 赔付表 | 存储在合约状态里可配置，不硬编码进字节码 | C 阶段实现；E 阶段标定数值 |
| 结算 calldata | 完整比赛记录本身：名次、玩家选的 `horseId`、完成时间、三次选牌、刷新位置、有效点击序列、结束原因与 `rulesVersion`；合约只校验长度上限，不解析。event 只带检索需要的字段：`Entered(raceId, player, stake, seed, rulesVersion)`、`Settled(raceId, player, rank, payout, rulesVersion)` | C 确认编码与上限；D 从链上取回并离线复算 |
| 卡牌作用域 | 玩家的卡可以写电脑马的瞬时运动状态（速度、位置、外部场乘子），**不得写八个性格参数、不得进入其目标速度函数入参**；反方向则完全禁止——玩家马的速度与体力计算不得读取任何电脑马状态。电脑马吃到的卡真实作用于它自己的速度，由高阻尼摊平、由区间钳住 | 已定案；自激的必要条件是双向，单向写入不闭合回路。承重墙是「玩家侧不读电脑马」那一条，写权限矩阵见[效果系统架构](../architecture/effect-system.md) |
| 效果系统 | 骨架（`src/race/core/`）+ 可插拔模块（`src/race/modules/`）+ 纯数据卡表（`src/race/cards/`）；模块按 id 字典序执行，模块清单与版本进 `rulesVersion` | 已定案；判据是「卡池为空时这段逻辑还需不需要存在」，需要即骨架。加一张卡的正常路径是加一条数据，不改骨架 |
| 数值算子 | 三种：直接加算、百分比加算、直接乘算；按固定阶段结算，同阶段内可交换 | 已定案；`mul` 是唯一边际递增的算子 |
| 机制覆盖 | demo 前把原语补齐到九类（含全局环境、跨马转移、条件触发），避免后续为一张卡回头重构 | 已定案；覆盖清单与三个已知缺口见[卡牌设计 §3.3](../card-design.md) |
| 装备与挂点 | 装备挂到马匹 rig 的具名插槽（躯干、四蹄、尾、轨道锚点等），资源缺失一律降级为占位 | 已定案；规则内核不 import 任何资源清单，否则美术进度会卡住数值调参 |
| 落后追赶触发源 | 按玩家自身相对基准配速的落后量 `lag(t)` 分档，不读电脑马状态 | 已定案 |
| 上链范围 | 两笔交易：`enterRace`（下注存入 Vault、交易内派生并存储 seed 与 `rulesVersion`）、`settleRace`（提交名次与比赛记录、按赔付表发放返还）；比赛过程中零交易 | 已定案 |
| 结算方式 | 两笔交易均由玩家钱包签名、前端广播，玩家付两笔 gas | C 验证本地链行为；D 验证真实预算与广播重试 |
| 随机信任 | `enterRace` 在交易内派生并存储 seed，绑定 player、raceId、chainId、合约地址与 `rulesVersion` | 已定案；含义是「运营方无法指定」，不等于可验证公平，产品文案不得混淆 |
| seed 重 roll | 不做防御。seed 只决定发牌，重 roll 的全部收益是换一手构筑 | 已定案；不值一个 EIP-2935 依赖 |
| 结算期限 | 无期限。seed 存在合约状态里，随时可重建本场的发牌 | 已定案；不需要窗口、过期状态或清理路径 |
| 弃赛处理 | 不调用 `settleRace` 即为弃赛，下注留在 Vault；无 `Abandoned` 状态、无退款、无 claim 路径；下一次 `enterRace` 直接覆盖该玩家槽位**并释放旧场的预留** | 已定案；`settleRace` 成功后删除槽位防重复结算。不释放旧预留则弃赛会永久占用偿付额度，最终锁死 `enterRace` |
| 奖金定义 | 总返还包含本金；最后两名 `G = 0` 仍以 value 为 0 调用 `settleRace`，只付 gas，留下完整链上记录 | D 前固定字段；E 前完成倍率定价 |
| 经济平衡对象 | 单个玩家在多场比赛中的累积 `E[G − B]`；CPU 不下注、不领取任何 MON | **demo 阶段不做标定**：测试网 MON 无价值，平衡是随玩法移动的动态目标，而链上这一侧已经把赔付表做成了可配置项。开放真实 MON 前才需要定价，见下方 //TODO |
| Vault 偿付 | 限制单笔最大下注，并在 `enterRace` 时要求合约余额足以覆盖最大赔付 | 已定案；维护一个 `reserved` 累加器，不构建逐场预留账本；偿付是可用性约束而非资金安全约束 |
| 视觉平台 | Web 二维横向竞速，优先桌面及移动横屏 | A/B 在实际目标设备检验八赛道可读性；竖屏提供旋转提示 |

## 4. 文档维护边界

当前正在执行的是[最小 Demo 计划](demo.md)，它覆盖本文 A、B 两阶段并把它们做成一个完整可玩的产品，边界在该文第 1 节；钱包管理已按 D 阶段的标准接上真实测试网，比赛的入场与结算在 C 阶段有合约之前仍是 mock。

玩法规则仅在[玩法设计](../game-design.md)定义，其中卡牌逐张的词条、数值与美术需求在[卡牌设计](../card-design.md)展开；模块与时钟在[架构](../architecture/overall.md)定义，效果模块的边界与写权限在[效果系统架构](../architecture/effect-system.md)定义；资金、交易与合约状态机在[链上文档](../chain-and-economy.md)定义；信任边界与将来加校验的升级路径在[无服务端探索](../_reaserch/serverless.md)定义。本文件只管理交付与验收，避免相同数值在多个文件反复复制。

探索文档对实现构成的硬约束有三条：主合约内不得出现任何玩法断言、电脑马速度不得以名次或目标完成时间为依据、规则以 `rulesVersion` 版本化并随场记录。要放宽其中任何一条，先在探索文档重新论证，不在本文件或玩法文档里单方面修改。

指导文档保持当前目标，不保留无用的迁移叙述。实施产生的证据应写入对应阶段的验收记录并链接，不能把建设目标改写成已完成。用户未授权文档修改且不是文档方向讨论时，不直接删改现有文档。

只有复杂且无法通过简单修改解决的错误、或验证失败会影响整体架构的问题才创建 `docs/_reaserch/` 文档。正文按「探索原因 / 探索目标 / 探索结果 / 复现说明 / 注意事项与补充」，必要时在末尾附核心实验代码与思路；临时实验实现验证后删除。该目录当前只有 `serverless.md`；它的 `//TODO` 在实测后就地更新为结果，不新开一篇结论文档。
