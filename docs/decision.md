# 项目决策

本文集中记录当前有效的产品、玩法、经济与技术边界。逐项规则和实施进度分别以[游戏设计](game-design.md)、[卡牌设计](card-design.md)、[链上架构](architecture/onchain.md)、[链上与经济](chain-and-economy.md)及[链上服务交付记录](plan/onchain-services.md)为准；历史推演和未决提案不视为当前决定。

## 产品与比赛

- 游戏是单人赛马：玩家选一匹马，其余四匹由电脑控制；电脑马不下注、不领取奖金。比赛固定五匹马，不提供马数或独立难度选择。
- 下注档位决定电脑马的开场性格区间。0 MON 是免费本地试玩；当前测试网有奖档位为 0.3、1、5、10 MON。
- 当前阶段正式上线范围仅为 Monad 测试网，不包含主网；创建账户自动领取 1 MON 测试币等测试网机制仍保留。主网部署属于后续独立阶段。
- gogo 只控制摄像机和输入反馈，不改变速度、体力、卡牌、随机数、里程或名次。动画、音效和渲染帧率均不进入比赛规则。
- 设计优先保证卡牌梗意图清楚、比赛过程有反馈；卡牌数值服务于可理解的效果。比赛结果由规则状态决定，不以玩家互相对抗或资产流通为核心玩法。

## 比赛规则与权威结果

- 有奖比赛由 Monad 上的 PonyGame/PaidRaceSolver 复算，PonyVault 按合约结算结果记账。浏览器只负责操作、动画与待确认预览；Envio 只作可回滚的历史和统计读模型，不决定资金或比赛终态。
- 不引入 Game Server、TEE 或结果签名者作为裁判。TypeScript 规则内核用于预览、测试和跨实现对照，不能替代 Solidity 验证。
- 规则输入来自开场 seed 与可验证区块哈希、实际选择交易时间与区块哈希，以及冻结的卡牌和五马规则。权威比赛时钟依据链上秒级时间；本地时钟、浏览器暂停、gogo 输入和客户端声称的名次均不构成结算证据。
- 结算按事件驱动求解整场五马冲线时间，不按浏览器帧或 50Hz tick 在链上回放。无动态场区间使用解析积分；重力井按实时距离影响五马耦合轨迹，以冻结的定点数值积分和事件定位处理，不取触发时距离快照。
- 结算保留物理排序 `rawRank`；合约验证【版本答案】后得到付款与战绩使用的 `settlementRank`。客户端不能写入特殊名次，也不能用浏览器名次决定奖金。
- 规则与赔率在开场时冻结。修改有奖规则须生成新的规则版本并部署新的求时器/Game；未完成会话继续由其原绑定版本结算或判负。

## 资金与账户

- 游戏只使用 Monad 原生 MON，不发行或依赖 ERC-20、WMON 等资产。下注、充值、提款与庄家注资都通过 payable 调用传入原生 MON，账本金额以 wei 记录。
- Vault 不设退款。无法结算、随机锚过期或玩家放弃的会话按返还 0 判负；判负与正常结算互斥，下注不会经退款入口返还。
- 当前测试网下注档位为 `0 / 0.3 / 1 / 5 / 10 MON`，第一名总返还倍率为 `[3, 1.5, 1, 0, 0]`（含本金）。这些是当前测试参数；最终返奖率结论在牌库与电脑马参数平衡后计算，不构成当前测试网发布门槛。
- Vault 分别记账用户可用余额 `A`、锁定下注 `L`、庄家流动性 `H` 和最大净赔付预留 `R`；持续满足 `Vault 原生余额 >= A + L + H` 与 `H >= R`。庄家只能提取未预留的 `H - R`。
- Mera 通行密钥 PRF 恢复根 EOA，保留既有派生路径和地址；Alchemy `sma-b` 是每条链独立的交易账户。根 EOA 不作为默认同址 EIP-7702 交易账户。资金、余额和交易发送方均明确使用原生 MON 智能账户。
- Agent Session Key 若启用，只能在期限与累计额度内调用 PonyGame 指定入口，不得任意转账、提款或修改 owner 权限。

## 卡牌与规则实现

- 五匹马共用同一规则和效果模型；玩家卡与电脑马卡均能按定义影响其他马，但不能改写开场冻结的性格参数。电脑马使用入场 seed 派生的三张私有牌堆，按自身里程顺序自动触发，不刷新、不进行玩家式策略选择。
- 玩家牌堆按冻结规则无放回派生。品质用于卡面表达，不改变抽牌概率；百分比效果先加总后乘基础速度，固定速度值在乘法之外相加。
- 有奖卡牌规则的唯一数据源是 `src/race/paid/cardRules.ts`；从该表生成 Solidity 规则表和一致性向量。修改卡牌规则时同步生成产物、向量和规则版本，不分别维护前端与合约的独立数值表。
- 经济与最坏 gas 验收按以下顺序进行：先补充牌库、平衡卡牌数值和电脑马性格；这些内容定稿后，再重算返奖率、构造最坏合法 gas 输入并确定验收门槛。上述计算不属于当前测试网上线门槛。
- 规则内核采用确定性事件与模块边界：随机数使用 seed 和用途域分离，不读取系统时钟或 `Math.random`；表现层只能读取规则状态，不能反向改变它。
- Phaser 只绘制赛道；选牌和结算卡面用 DOM 组件复用；分享海报由离屏 Canvas 绘制，不截取页面 DOM。
- 美术资源缺失时表现层降级为占位素材，不能阻断或改写比赛规则。

## 身份、图鉴与服务

- 钱包身份使用单一正式域名 `ponygo.kiruno.cc`。WebAuthn PRF 与 `rpId` 绑定；换域名会派生不同账户，域名变更不视为无缝迁移。
- 图鉴使用独立于钱包的 PRF 命名空间派生加密与签名密钥。浏览器加密图鉴内容，D1 只保存密文及验签、版本管理所需的公开元数据；Worker 通过一次性挑战验证签名，并用版本号条件写入处理并发更新。
- 合约/RPC 是会话和资金状态的权威来源。索引器、浏览器缓存和 Worker 存储都不能代替合约状态；图鉴密文不构成链上卡牌所有权证明。
- 网站使用 Vite/React/Phaser；有奖规则使用 TypeScript 参考实现与 Solidity/Foundry 合约；静态站点、图鉴 Worker 和 D1 部署到 Cloudflare。

## 素材与脚本布局

- `art-src/` 是作者本地保存的美术母版，不纳入 Git。运行时素材由脚本生成到 `public/assets/` 并随项目版本管理；正常开发与部署使用已提交的运行时素材。
- Wrangler 的 Worker 与 D1 迁移统一放在 `scripts/Wrangler/`：Worker 入口为 `scripts/Wrangler/worker/collection.ts`，迁移目录为 `scripts/Wrangler/migrations/`。根目录 `wrangler.toml` 是 production/preview 部署配置的唯一入口。
- Foundry 脚本统一放在 `scripts/`；当前 PonyGame 部署入口为 `scripts/DeployPony.s.sol`，由 `foundry.toml` 的脚本目录配置发现。其他应用开发、资源与运维脚本也放在此目录，按文件类型和入口区分用途。
