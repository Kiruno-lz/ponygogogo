# 玩法设计

## 1. 产品范围

核心体验是“跟随自己的马横向竞速，用三次选牌改变五匹马的冲线顺序，用 gogo 调整跟随镜头的构图”。目标是最快到达终点。

每场固定五匹马，玩家选其中一匹，其余四匹为电脑马。下注档位（0.3 / 1 / 5 / 10 MON）只决定下注额；电脑马与玩家共用同一基线，速度上限由入场区块哈希随机决定（§5.3）。0 档为免费本地试玩，使用与有奖场相同的事件求时器，只在本地运行。有奖场次的名次由合约按链上输入独立复算并付款（[链上架构 §5](onchain.md)），浏览器负责交互、表现与预览。

**设计主线是反馈，不是收益模型。** 下注制造赛前紧张，抽卡制造中段决策，gogo 保留持续的镜头交互，结算卡片给终局确认；gogo 的动效与音效不得暗示它改变速度。

本作是单人游戏，不存在玩家之间的对抗：电脑马不下注、不领取任何 MON，只负责提供一场有张力的追逐。社交与流通性来自卡牌、图鉴与结算海报的分享。

画面采用二维横向赛道和马匹动画，用分层背景形成纵深。赛道数等于马匹数，每匹马占一行；行与行之间没有碰撞，也没有连续变道动画，唯一改变站位的是【交换】的瞬时置换（§3）。摄像机只沿横轴跟随玩家：玩家马默认位于画面左起三分之一处；gogo 点击密度越高镜头越向左、玩家马越靠右，最多推到三分之二；点击停止后密度按秒级衰减，镜头平滑回到默认构图，减少动态效果时不推移。所有马共享同一镜头位移，相对位置、速度、里程和名次不变；纵轴与缩放固定。右侧名次榜列出五匹马的当前名次。gogo 不进入体力、速度、随机数、事件表或结算输入。

## 2. 开始界面与比赛流程

加载页以 ENTER 门进入（同时解锁音频），竖屏时显示旋转提示。首页包含开始游戏、卡牌图鉴与游戏设置；设置提供主音量、背景音乐、音效三档音量，以及语言、减少动态效果与静音，不提供难度或马数选择。

未登录时首页并排显示注册与登录，各走一条 Mera 通行密钥路径：注册先弹取名窗口（默认 `ponygogogo`，只是认证器列表里的标签），确认后建通行密钥并请求一次测试币，受理与实际到账分别提示；登录唤起同一把通行密钥回到同一地址，有多把时由系统列出供玩家挑选。通行密钥不落盘，刷新页面后需重新登录。登录后木牌显示地址（前 6 字符…末 4 位）与链上 MON 余额，退出登录在木牌上；点开木牌是钱包面板：完整地址（可复制）、网络、智能账户原生 MON 余额（可刷新）、重新领币、导出助记词，配置索引器时另显示最近战绩。

免费本地试玩不碰任何余额，不调用钱包或 Vault，也无需登录。有奖场次由 sma-b 直接以原生 MON 支付下注，Vault 只锁定本场下注与赔付预留，结算直接付款到智能账户；每次实际选牌提交链上交易，入块回执与合约事件决定资金状态和最终名次。

1. **选马。** 已开放角色洗牌成队列，页面显示五名可见窗口，用箭头或 ↑/↓ 移动；窗口内五名即本场名单，选中角色后显示其初始能力（§6）。
2. **下注。** 选择档位（0 为免费试玩），页面显示钱包余额与第一名最高返还。合约未部署、规则哈希不兼容、未登录或仍在确认部署时，有奖档位灰显并给出原因。
3. **开场。** 试玩在本地建立比赛状态；有奖场次调用 payable `PonyGame.openSession`，绑定名单、选中马、档位与 seed。余额不足时在发送开场交易前拦截，倒计时处显示入场失败并提供返回。起跑倒计时 3 秒；有奖开场交易未入块时倒计时停在“1”。规则时间从入场块时间 `T0` 起算，倒计时只是表现，结束后画面追上规范时间。
4. **比赛。** 浏览器按同一规则版本渲染五匹马；电脑马不运行追赶逻辑，只有跨马卡牌效果（如 C-06、C-10、C-34、C-35）读取其他马的位置。gogo 按钮在倒计时、选牌面板开启与冲线后隐藏。
5. **检查点。** 玩家里程到达检查点时打开选牌面板（§4），在链上窗口内提交选牌或主动放弃；超时按冻结规则处理，不由浏览器补写选择。
6. **冲线。** 玩家冲线时展示浏览器预览名次并播放旋律（第 1–2 名 `jingle_win`，其余 `jingle_lose`，只播一次）；有奖场显示“待链上验证”，预览名次不视作已付款事实。
7. **结算。** 有奖场次提交结算交易，合约独立复算五马冲线顺序并计算返还；试玩只在本地结算，不产生链上奖金。
8. **分享或再来一场**（§8）。

比赛中的退出按钮需二次确认。试玩在页面隐藏时终止并提示；有奖会话不因离开而终止，回到前台后画面按链上规范时间追赶。重新登录后首页弹出未完结会话的恢复窗口，提供继续观看、直接结算与稍后处理；可付款会话的选择、随机值与结算期限以链上状态为准，刷新或关页不抹掉已上链选择（[链上架构 §8](onchain.md)）。

## 3. 赛道、里程与名次

赛道长度 `L = 100000`。**检查点不是赛道上的位置，是每匹马自己跑过的里程。** 每匹马维护两个独立的量：

| 量 | 定义 | 用途 |
| --- | --- | --- |
| `pos` | 当前在赛道上的位置 | 冲线判定、名次、镜头、身位差 |
| `dist` | 自身速度对模拟时间的积分；交换造成的位置跳变不计入 | 检查点抽卡 |

`dist` 跨过 25000、50000、75000 各触发一次抽卡，一场最多三次，同一档不重复触发。两个量分开带来三个直接结果，都是有意的：

- **跑满 100% 里程不等于冲线**：被换到后面的马可能跑够了整条赛道的距离仍未到终点。
- **没跑满 100% 里程也可以冲线**：被换到前面的马 `pos` 大幅前移，之后只需跑完剩余位置差。
- **提前冲线的马可能拿不满三次抽卡**：冲线时自身里程未达 75000 的马会少一次或更多抽卡，这是用抽卡机会换捷径的代价，不做补发。

来回交换刷不出第四次抽卡，被换到后面也不会重复触发已消费的档位。里程跨越使用规则状态检测，不依赖动画或像素位置。

**赛道是站位，不是身份。** 马由 `horseId` 标识；`laneIndex` 是可变的上下站位，开局为 `0..4` 的固定排列，只能由【交换】修改（交换同时置换两匹马的 `pos` 与 `laneIndex`）。`laneIndex` 只用于 C-09 抽取交换目标、C-06 炸弹的赛道归属判定与渲染排布；运动公式、里程累计与同刻冲线排序不读取它。

五匹马由同一份运动规则求出各自首次满足 `pos ≥ L` 的冲线用时 `finishTime_i`（整数毫秒）。按 `(finishTime_i, horseId)` 升序得到物理排序 `rawOrder`。【版本答案】由合约从实际获得的卡牌集合判定，触发时把玩家置于结算排序 `settlementOrder` 第一，其余马保持物理相对顺序；未触发时两者相同。奖金与战绩使用结算排序，同时保留五个冲线用时与物理排序，客户端不能提交名次。冲线时间的求解方式见[效果系统 §5](effect-system.md)。

玩家冲线后封存选牌输入，Buff 不影响已完成马匹。电脑马继续跑完剩余距离；尾场只用于生成完整五马排名，不改变已确定的玩家名次。

## 4. 检查点抽卡

玩家里程跨过检查点时，展示三张不同 cardId 的牌，最多选一张；一场实际选择 0–3 张。超时用显式 `null` 记录，不能伪装成选了默认牌。电脑马不打开面板：每匹电脑马持有 3 张私有牌，在自己的里程档按顺序自动取牌并立即生效，不刷新、不等待、不做三选一。

**发牌是一副 14 张的有序牌堆加一个游标，不是三次独立抽取。** seed 与入场区块 `b_0` 的哈希派生 `deck[0..13]`，十四张互不重复；游标 `cursor` 从 0 开始，每个检查点从游标处连取三张展示，选择或放弃后游标前进 3。正常打完一场消耗 9 张，余下 5 张是刷新的预算：刷新维护另一个反向游标 `tailCursor`，从最后一张往前取。

```
deck[12], deck[13] ← 从稀有子集中无放回取 2 张      // 保底
deck[0..11]        ← 从剩余全部卡中无放回取 12 张
全部取牌用 H(seed, blockhash(b_0), 0, "card", 位置) 定序，位置按上面两步的顺序编号
```

**抽取顺序是派生式的一部分。** 无放回意味着第 k 张取决于前 k−1 张，复算方必须按同一顺序走完十四次；换顺序就是换发牌规则，要跟着换规则集哈希。卡池下限由此确定：**总卡池 ≥ 14 张，稀有子集 ≥ 2 张**。前十二张仍可能出现稀有卡，牌堆不会被保底抽成两段。

**每次刷新只替换一张候选。** C-05 增加 3 次刷新额度，角色 Shadow 开局拥有 1 次，两者累加。每次从 `deck[--tailCursor]` 取一张，另外两张与正向游标不变；同一面板同一位置最多刷新一次，一个面板最多刷新三个不同位置；牌堆空间不足时禁止刷新。尾部前两张是稀有保底，因此本场前两次实际刷新取到稀有牌，之后没有品质保证。

- 选牌面板开启时全场模拟时间以现实时间的 0.1 倍推进，运动、体力收支、卡牌持续时间与自动触发计时一起慢放；20 秒选择限时按现实时间计算。效果的 2 秒、30 秒等持续时间均以模拟时间计。
- 面板开启期间若又越过检查点，该检查点推迟到当前面板关闭后按顺序打开；玩家冲线会收起面板。
- 玩家选择或主动放弃时提交交易，该交易的入块秒是权威动作时间，入块区块哈希是该卡随机效果的锚。本地点击时间只用于未确认动画。窗口取整、随机锚派生与可验证期限见[链上架构 §4](onchain.md)。
- 没有有效选择时在窗口截止时按固定规则放弃；自动选牌从此前已锁定的随机锚派生，不依赖新的交易时机。

## 5. 运动、体力与电脑马

### 5.1 速度公式

每匹马的**性格**在入场时锁定：起始基础速度 `b₀`、基础加速度 `a_i`、基础速度上限 `C_i` 与体力参数，赛中不可被卡牌改写。规则只在效果、体力和卡牌状态发生离散变化时重新建立运动区间；区间内：

```text
b_motion,i(τ) = min(C_i, b_motion,i(τ₀) + a_eff,i·(τ − τ₀))
a_eff,i = 0（力竭或已满速）；150（死亡/力竭后恢复至上限）；否则 a_i
P_i(τ) = Σ 当前生效的百分比速度修正         // +30% 与 +40% 合计 +70%
B_i(τ) = Σ 当前有效的固定速度；b_i = b_motion,i + B_i
K_i(τ) = Σ 当前有效的额外速度
v_i(τ) = max(0, b_i(τ)·max(0, 1 + P_i(τ)) + K_i(τ))
Δpos_i = ∫ v_i(τ) dτ；Δdist_i = 同一运动积分，不含交换造成的位置跳变
cost   = 20/s × max(0, 1 + Σ消耗修正)
regen  = (力竭 ? 15/s : 10/s) × (1 + Σ恢复修正)
```

`C_i` 只限制运动基础速度 `b_motion`。固定速度 B 参与百分比乘法，额外速度 K 在乘法之外相加；贡献随来源期限结束，卡牌修正后的总速度可以超过基础上限。各卡如何写入 P/B/K 与体力修正见[卡牌设计 §3.2](card-design.md)。实际整数舍入、阈值定位与单位换算见 `src/race/paid/motion.ts`、`resources.ts` 与 `PaidRaceMotion.sol`。

### 5.2 当前参数

参数来自 `src/race/paid/playerBalance.ts`（生成 `PlayerBalance.sol`），由 `solver.ts/createState` 按名单初始化五匹马。

| 参数 | 当前值 |
| --- | --- |
| 赛道 / 检查点 | 100000 / 25000、50000、75000 |
| 起速 / 常规加速度 | 300 / 150 |
| 运动基础上限 | 玩家 1800；电脑马见 §5.3；角色上限修正另计 |
| 初始体力 / 容量 | 300；玩家奶龙为 400，电脑马奶龙没有容量加成 |
| 常规消耗 / 恢复 | 20/s / 10/s，分别应用消耗与恢复修正 |
| 超容量期间 | 消耗减半，不恢复 |
| 力竭 | 体力见底时进入：停止消耗、恢复 15/s、加速度 0、运动基础速度立即钳至 1200 |
| 力竭退出 | 体力达到 135；当刻速度不变，再以 150 加速度恢复至自身上限 |
| 死亡 | 运动基础速度归零，以 150 加速度恢复；位置、里程、B/K 与卡牌期限保留 |
| 重生免疫 | 5000 ms |
| 求时上限 | 600000 ms 模拟时间；未冲线马按 600001 ms 排序 |

体力按模拟时间消耗与恢复，选牌慢放同时影响两者。直接体力补给允许超过容量，持续恢复钳至容量。【亢奋】使体力不低于 1 并解除已有力竭；【来劲】在 30 秒监听内首次将进入力竭时补给 250 并拦截一次。死亡不清除、重置或延长任何卡牌效果、B、K、装备层数、阶段、监听与里程进度。不带名单的低层测试输入使用另一组默认参数（容量 1000、消耗 24/s），不用于生产入场。

### 5.3 电脑马

四匹电脑马与玩家马使用同一运动公式与体力基线，只有运动基础上限额外加独立整数偏移：

```text
C_cpu = 1800 + 100 + H(seed, openAnchor, 0, "horse.cap", group) mod 401
```

`group` 按非玩家槽位升序编号 0–3，四个上限按剩余 `horseId` 升序分配，因此无论玩家选哪个槽位，本场遇到的上限集合相同。角色能力（如牛来的上限与消耗修正）对电脑马同样生效。下注档位不改变偏移区间；0 档试玩用本地锚按同法派生。

电脑马不运行橡皮筋、目标速度、阻尼或逐 tick 噪声，赛中不按玩家位置或名次调速；私有牌堆从 CPU 可用子集派生，按 `horseId` 区分，与玩家牌堆使用独立用途域。玩家的卡可以炸停电脑马、与它交换位置、用重力井拖慢它，电脑马的卡同样可以作用于玩家；任何卡都不得改写入场冻结的性格参数。

### 5.4 数值复算入口

规则数值以 TS 规范表及生成的 Solidity 表为准；统计产物只代表生成时的规则哈希、输入与策略，旧规则下的胜率、返还率或 gas 不能沿用。

| 入口 | 用途与输出 |
| --- | --- |
| `scripts/analyze-numerical-balance.ts` | 生产求时器的受控单卡、组合、刷新与进程内候选参数比较；`--out` 默认 `.cache/balance-refresh`，`--optimization-audit` 另写 `optimization.json` |
| `scripts/analyze-paid-card-builds.ts` | 构件取得、门控与覆盖统计，固定输出 `tests/vectors/paid-card-builds.json`；`--check` 校验是否过期 |
| `scripts/analyze-pony-balance.ts` | 角色配对与策略比较（使用 `pony-balance-planner.ts` 库与进程内无能力对照角色） |
| `scripts/analyze-pony-strategies.ts` | 完整名单枚举与固定策略比较，复现见[策略研究](../_reaserch/pony-strategy-validation.md) |
| `scripts/calibrate-cpu-difficulty.ts` | 对上限偏移区间采样，结果写入 `--out` 目录（默认 `.cache/cpu-difficulty`），`--summary` 汇总该目录 |
| `scripts/measure-paid-solver.ts` | `check:solver-monad` 的实现：80 场生产输入的结果与 Monad gas，不能替代真实交易验收 |

受控单卡、强制组合与自然派生对局分别报告；单卡标称百分比不能直接当成全程收益，有限样本的最佳观察名单不是理论最优名单。`calibrate-cpu-difficulty.ts` 的前瞻策略只对部分随机卡平均预测锚，并给对手注册无能力实验角色，结果不能作为任意策略的收益上界。

## 6. 角色与初始能力

角色目录有九名，使用稳定 `ponyId`；比赛中的 `raceHorseId` 是五个参赛槽位，角色名称、能力与素材按 `roster[raceHorseId]` 查询。名单由五个不同且启用的角色组成，开场冻结，不随交换变化。默认开放 ponyId 0–4，其余由链上获得物与已解密图鉴解锁；解锁只是客户端限制，合约只校验“已启用且不重复”。显式 `?seed=`（`0x` 加 8–64 位十六进制）同时固定选马队列，使名单与规则输入可复现。

能力数值以 `src/race/paid/ponyRules.ts` 为唯一来源，生成 `contracts/libraries/PonyRules.sol` 并进入规则哈希；名单本身是开场输入。玩家与电脑马都按名单取得能力，但初始刷新与奶龙容量加成只用于玩家。卡牌“主功能”分类见[卡牌设计 §8.1](card-design.md)。

## 7. 卡牌构筑

三次“3 选 1 或放弃”是玩家改变比赛规则状态的唯一途径；gogo 不改变成绩。规则表属于版本化比赛配置，正在进行的比赛不得被热更新改变。

构筑的深度不在候选组合数（每点必选一张且不刷新时为 3³ = 27 种，允许主动放弃时为 4³ = 64 种），而在**时机与叠加顺序**：

- 一副牌堆内十四张两两不等，不重复出现同一 cardId。
- 同时生效的百分比效果先加总再乘基础速度，生效时间与时长决定分段结果；发牌修正卡的价值随检查点递减。
- 持续时间有限而赛道分段固定，一张强牌放在第一个还是第三个检查点，覆盖的路程完全不同。
- 体力是构筑的预算：高增益卡的代价基本记在体力上，第三个检查点的选择往往由前两次的体力开销决定。

当前卡池为 40 张（C-01 至 C-40），13 张稀有、27 张普通，30 张可进入电脑马私有牌堆。品质只有普通与稀有两级，唯一的品质约束是牌堆末两张取自稀有子集；品质分布不随下注金额变化。逐张规则、状态词条与美术需求见[卡牌设计](card-design.md)。

**任何马的自主速度与体力计算不得读取玩家点击或镜头状态。** 跨马卡牌可读取和改写五马状态，必须进入链上规则，不能只在渲染层体现：

| 卡牌可以写 | 卡牌不得写 |
| --- | --- |
| 任意马的当前速度修正、位置、体力与装备 | 入场时冻结的性格参数 |
| 全场环境与赛道实体 | 随机锚、历史选牌与结算期限 |

负面效果可以让速度瞬时归零，随后立即重新起步（【死亡】即如此）。“跳过检查点”在里程制下不可能发生。

## 8. 结算与社交

结算页显示完成时间、名次、至多三次选择（含放弃与因里程不足而未发生的那次）、下注额、总返还、净盈亏与交易状态；有奖场另显示结算交易及浏览器链接。资金状态用一枚短印章表达：结算中、已结算、结算失败、已判负，试玩为“本地试玩”；不展示虚构交易，不把预计奖金标成已到账。按钮行下方另起一行显示结算期限、失败说明与「重试结算」，以及预览名次与链上不一致的提示；试玩触发【版本答案】时显示标记。尾场演出或网络延迟不能阻塞关闭面板与后续恢复查询。

正常有奖结算获得稀有卡或角色时弹出获得窗口，读取失败可重试；获得物进入图鉴，图鉴分卡牌与角色两页，解锁的角色进入选马队列。获得规则见[链上架构 §6](onchain.md)。

分享按钮打开海报浮窗，生成 1620×971 的 PNG。海报由离屏 Canvas 在预制美术上绘制：马匹立绘、奖章、WIN/FINISH 美术字标题（第一名且试玩或净盈利为 WIN，其余为 FINISH）、“Great Run, {name}!” 一行、金额、确认的获得物与固定二维码。试玩金额处写“免费试玩”，有奖写链上结算的净盈亏，未最终确认时写“待链上验证”。海报不暴露操作流水或钱包秘密。

浮窗提供复制图片、保存 PNG，以及跳转 X、Instagram 与小红书的入口。X 的网页入口只带文字，图片由用户粘贴或上传；Instagram 与小红书没有网页分享接口，只打开站点。分享由用户主动触发，应用不自动发帖。
