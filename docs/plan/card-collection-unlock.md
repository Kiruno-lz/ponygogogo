# 通行密钥图鉴与稀有卡奖励

## 当前状态

图鉴的加密身份、密文同步和 D1 条件写入已实现；`scripts/Wrangler/worker/collection.ts` 是 Worker 入口，迁移在 `scripts/Wrangler/migrations/`。preview Worker 与 D1 已通过协议测试。生产 Worker 的部署、正式域名上的真实通行密钥读写和真实双设备验收仍未完成。

稀有卡奖励和按玩家收藏筛选比赛牌池尚未实现，也不是当前有奖比赛的输入。当前比赛规则使用公开、冻结的规则卡池；通行密钥图鉴是个人进度，不构成链上所有权证明。旧文档中的本地 `ChainPort` 方案、`[0, 1, 5, 10] MON` 奖励档位和对应概率表均已废止，不应作为代码或产品规则依据。

## 已采用的图鉴数据边界

- Mera 通行密钥 PRF 派生两种独立用途的材料：AES-256-GCM 图鉴加密密钥与 Ed25519 同步身份。不得从钱包私钥、助记词或钱包默认 PRF 派生。
- 浏览器加密图鉴内容；D1 只保存公钥、版本、IV、密文和公开格式元数据。明文收藏和解密材料只在浏览器内存中使用。
- Worker 通过一次性签名挑战验证读写请求。签名绑定来源、路由、挑战 ID 和载荷；写入使用 `expectedVersion` 条件更新，版本冲突返回 `409`，不得盲写。
- D1 密文和签名身份用于隐私存储与访问控制，不证明收藏获得合法，也不证明链上卡牌所有权。
- 更换正式域名会改变 WebAuthn `rpId` 和账户派生结果；正式域名固定为 `ponygo.kiruno.cc`。

## 当前接口与配置

| 接口 | 作用 |
| --- | --- |
| `POST /api/collection/challenge` | 创建短时、一次性签名挑战，不包含收藏数据 |
| `POST /api/collection/read` | 验签后返回密文与版本，或返回未建档状态 |
| `PUT /api/collection` | 验签并按 `expectedVersion` 创建或更新密文 |

根目录 `wrangler.toml` 指向 Worker 与 production/preview D1。API 路由由 Worker 处理，其他请求交给静态资源。部署步骤与配置位置见[部署文档](deploy.md)。

## 尚未决定的稀有卡功能

私有收藏若改变有奖比赛的可抽卡集合，就会影响公开复算。当前链上协议没有证明 D1 私有集合成员资格的机制，因此不能按私有收藏筛选有奖牌池，也不能把 Worker 同步成功当成派奖凭证。

未来若要启用有奖稀有卡，须先确定可公开验证的资格证明与奖励来源，再单独决定命中率、权重和发放规则；现有旧概率表不生效。未作出这些决定前，图鉴仅保存个人收藏数据，不影响有奖比赛输入或返奖。

## 验收门槛

- Worker/D1 production 部署完成，并在 `ponygo.kiruno.cc` 验证正式配置与迁移。
- 真实通行密钥完成首次写入、重新登录读取、解密恢复和版本冲突恢复。
- 第二台设备通过同一账户恢复加密收藏；不同身份不能读取或解密。
- 断网、解密失败、未知格式和同步冲突均保留原密文，不重置为空集合、不报告未确认奖励为已获得。
