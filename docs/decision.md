# 项目决策

本文集中记录当前有效的产品、玩法、经济与技术决策，每条只写决定本身与边界；具体规则、参数与实现以docs/architecture下的文档为准。历史推演和未决提案不视为当前决定。
本文只记录特殊决策，并非做产品的完整定义，目的是防止项目偏向错误方向。

## 产品与比赛

- 对于玩家参与的情况：
  - 游戏是单人赛马。
  - 角色与稀有卡共用解锁的流程。
  - 开赛时选马窗口内的五个角色组成固定名单。
  - 下注档位只决定下注额，0 MON 免费本地试玩按本地锚同法派生。
  - 电脑马与玩家共用同一基线，四匹的速度上限由开场交易所在区块的哈希独立加偏移，不随档位变化。
  - 当前上线范围仅为 Monad 测试网，不含主网；注册时向智能账户请求测试币，余额以 RPC 为准。
  - gogo 只控制摄像机和输入反馈，不改变速度、体力、卡牌、随机数、里程或名次。动画、音效和渲染帧率均不进入比赛规则。

- 对于agent无头模式参与的情况：
  - 游戏为链上进行，暂时不设置浏览器渲染，
  - 开赛条件：匹配到5名agent，PonyVault确认皆下注成功。

## 比赛规则与权威结果

- 有奖比赛由 Monad 上的 PonyGame/PaidRaceSolver 复算，PonyVault 按合约结算结果直接向玩家智能账户付款。
- 规则输入来自开场 seed 与可验证区块哈希、实际选择交易的秒级时间与区块哈希、五名参赛者的角色名单，以及冻结的卡牌、角色能力与玩家基线。客户端声称的名次不构成结算证据。
- 结算按事件驱动求解整场五马冲线时间，不按固定步长或浏览器帧在链上回放。无动态场区间解析积分。
- 重力井区间使用步长不超过 250 ms 的定点 RK2，步长纳入规则哈希。
- 结算保留物理排序；合约验证【版本答案】后得到付款与战绩使用的结算排序。客户端不写入特殊名次。
- 规则与赔率在开场时冻结。修改有奖规则须生成新规则哈希并部署新的求时器、Game 与 Vault；
- 求时器部署为单个 `PaidRaceSolver`：Engine 唯一持有比赛状态，Motion、watch/gated 与冷路径 `PaidRaceCold` 编为内部库；不独立部署辅助合约，不引入组件注册表或 DELEGATECALL。体积按 Monad 上限验收（runtime ≤ 131,072 B、initcode ≤ 262,144 B），执行 gas 以 Monad 计价验收。
- 浏览器只负责操作、动画与待确认预览。
- Phaser 只绘制赛道；卡面、选牌面板、图鉴与获得窗口使用 DOM 卡面组件（`src/cards/Card.tsx`），HUD 与结算页以图标和名称展示卡牌；分享海报由离屏 Canvas 绘制，不截取页面 DOM。

## 资金与账户

- 游戏只使用 Monad 原生 MON，不发行或依赖 ERC-20、WMON，金额以 wei 记录。
- 玩家在 `PonyGame.openSession{value: stake}` 中一次支付完整下注，Game 同笔转入 Vault；结算时 Vault 直接向玩家智能账户付款，接收失败按实际返还 0 完成结算，不保留补领入口。
- 玩家下注后，无论任何情况，Vault 不设置返还/退款。只有在 PonyGame/PaidRaceSolver 复算判断符合有奖情况下 Vault 才有转出。玩家在结算交易完成前退出比赛、切换界面等可能出现作弊风险情况下，Vault 没有发奖金的义务。
- Vault 不设玩家充值、可用余额、提款或退款入口，下注前玩家的一切资金在自己钱包，比赛获得的奖金直接发到玩家的钱包。
- Mera 通行密钥 PRF 恢复根 EOA，保留既有派生路径和地址；Alchemy `sma-b` 是每条链独立的交易账户。根 EOA 不作为默认同址 EIP-7702 交易账户。

## 卡牌与规则实现

- 五匹马共用同一规则和效果模型。电脑马使用入场锚派生的三张私有牌，按自身里程自动触发。
- 玩家牌堆按冻结规则无放回派生：末两张取自稀有子集，前十二张从其余牌中抽取，品质不另行加权。
- 卡牌规则的唯一数据源是 `src/race/paid/cardRules.ts`，角色能力是 `ponyRules.ts`，玩家基线是 `playerBalance.ts`；Solidity 规则表与一致性向量由它们生成，不分别维护前端与合约的数值表。
- 规则内核采用确定性事件求时器与单一规则表：随机数使用 seed 和用途域分离，不读取系统时钟或 `Math.random`；表现层只能读取规则状态，不能反向改变它。

## 身份、图鉴与服务

- 钱包身份使用单一正式域名 `ponygo.kiruno.cc`。WebAuthn `rpId` 绑定域名；换域名会派生不同账户，不视为无缝迁移。
- 有奖正常结算独立抽取稀有卡或非默认角色，由链上 `PonyRewards` 记录；获得物不决定入场资格、返奖或名次。图鉴与选马读取默认开放集合、链上位图与已解密收藏的并集。
- 图鉴使用独立于钱包的 PRF 用途域派生加密与签名密钥。浏览器加密图鉴内容，D1 只保存密文及验签、并发控制所需的公开元数据
- 合约/RPC 是会话和资金状态的权威来源。索引器、浏览器缓存和 Worker 存储都不能代替合约状态；图鉴密文不构成链上所有权证明。
- 网站使用 Vite/React/Phaser；有奖规则使用 TypeScript 参考实现与 Solidity/Foundry 合约；静态站点、图鉴 Worker、Keeper 与 D1 部署到 Cloudflare。

## 素材与脚本布局

- `art-src/` 是本地保存的美术母版，不纳入 Git。运行时素材由脚本生成到 `public/assets/` 并随项目版本管理；正常开发与部署使用已提交的运行时素材。
- Wrangler 的 Worker 与 D1 迁移统一放在 `scripts/Wrangler/`，根目录 `wrangler.toml` 是 production/preview 部署配置的唯一入口。
- Solidity 具体合约留在 `contracts/` 根目录，内部库、抽象继承模块与接口分别放在 `contracts/libraries/`、`contracts/abstracts/`、`contracts/interfaces/`。Foundry 脚本统一放在 `scripts/`（PonyGame 部署入口为 `scripts/DeployPony.s.sol`，由 `foundry.toml` 的脚本目录配置发现）；其他开发、生成、分析、素材与运维脚本也放在此目录。
