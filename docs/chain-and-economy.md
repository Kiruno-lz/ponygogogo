# 链上与经济

## 1. 权威结果

有奖比赛使用 [PonyGame 与 PonyVault](architecture/onchain.md)。PonyGame 依据已锁定 seed、各次选择的交易入块号和可验证区块哈希、冻结的卡牌/五马规则，独立计算排名，再按开场时锁定的赔付表指示 Vault 返还。浏览器名次只供预览或作为结算断言，不能直接决定奖金。Envio 只负责查询。当前代码仍是本地 mock，没有真实链上复算与真实奖金。

一场不再只有两笔交易：开场、每个实际触发的选择/放弃和最终结算都需要链上输入；随机锚可并入下一次选择或结算，若即将超出可读区块窗口则单独封存。浏览器画面的 gogo 点击不产生交易，不进入规则记录。

## 2. 会话与数据

开场绑定 `sessionId`、玩家智能账户、选中马、下注、最大返还预留、赔率与 `rulesetHash`、卡集合承诺、seed、入场区块 `b_0`、其时间戳 `T0` 和期限。`H(seed, blockhash(b_0), 0, purpose, eventIndex)` 确定初始牌堆和基础参数。每个实际选择/主动放弃记录刷新动作、`cardId | null`、交易入块号 `b_i` 与时间戳 `Ti`；超时、自动选牌、断卡、未到达检查点必须区分。对实际选择的随机锚，在后续区块用 `blockhash(b_i)` 校验并保存哈希，按 `H(seed, blockhash(b_i), i, purpose, eventIndex)` 派生随机效果。自动选牌只取此前已锁定的锚；超时不另造随机锚。临近 EVM 直接可读窗口边界前封存，逾窗不得接受客户端补报哈希。

比赛模拟时间由真实经过时间推导，不从区块高度换算：正常 `dτ/dt=1`，选牌慢放为 `0.1`；检查点打开时刻由上一段规范赛马状态推导，20 秒后超时。合约以 `T0/Ti` 的链上秒级时间建立求时区间，浏览器用高精度时钟预览并在交易确认后校正。浏览器暂停或改本地时钟不能改变已入块选择的规范时间；链上时间本身不能证明毫秒级点击时刻。

`settleSession` 从上述输入直接求五马量化冲线时间并按 `(finishTime, horseId)` 排出 `rawRank`；合约再从已获得卡牌验证【版本答案】并生成用于付款的 `settlementRank`。无重力井时按事件区间解析积分；重力井生效时按实时距离做冻结规则的定点数值积分，不逐 tick 清算。调用者可附声明名次和 witness，但合约必须检查，不能信任其输出。结算只针对仍开放且已满足完赛/期限条件的会话，成功后不可再次结算。过期退款与结算互斥；不得通过“再入场覆盖旧记录”挪走原下注。所有金额与舍入使用最小单位整数和开场冻结的规则版本。

## 3. Vault 与偿付

Vault 保管固定 ERC-20，记录玩家可用余额 `A`、锁定下注 `L`、庄家流动性 `H`、未结算最大净赔付预留 `R`。始终维持 `token.balanceOf(Vault) >= A + L + H` 且 `H >= R`；单场预留为 `max(maxPayout - stake, 0)`。开场先锁下注和预留；结算或退款原子释放；庄家仅能提取 `H-R`。玩家返还按会话冻结赔率计算，不能由前端给出 payout。充值、提款和管理员操作不得改写已开场赔率与玩法。

下注 `B`、该场冻结的名次总返还倍率 `M[r]`（basis points）给出 `G = floor(B × M[r] / 10000)`；`G` 包含本金，单场净盈亏为 `G − B`，链上 gas 另计。倍率不在本轮调整。开场时按全排名中最大 `G` 预留庄家净赔付；合约复算排名后只选对应倍率，不接受客户端自报 `G`。

## 4. 交易生命周期

界面分别显示交易已提交、已入块、已最终确认；冲线时浏览器可展示“待验证”预览，不得将预估奖金标记为到账。网络返回不确定时用账户、sessionId、调用 ID 与交易哈希读取合约状态，再决定是否重试。结算失败应保留原会话及可复核输入，不创建新场绕过失败。待退款会话走显式退款路径。不要以 Envio 索引进度判定资金终态。
