# 卡牌与效果系统设计

本文承载[玩法设计第 6 节](game-design.md)的展开：效果原语、状态与装备词条、卡牌清单与美术需求。玩法总纲（里程检查点、牌堆发牌、慢放、体力预算）以玩法设计为准，本文不重复。模块边界与扩展点在[效果系统架构](architecture/effect-system.md)。

## 1. 设计目标

**卡牌是本作的核心玩法，创意来源是 meme。** 一张卡成立的第一判据不是数值曲线，是玩家看到卡面的瞬间认出这是什么梗、并且知道接下来会发生什么好笑的事。数值服务于这个瞬间，不反过来。因此本文允许出现「30 秒后必定死一次」这种在纯平衡视角下不合理的设计——它是梗的一部分。

**状态之间的交互是构筑的第二层。** 【起飞】免疫炸弹不是特例补丁，是这一层的第一个例子：卡牌之间通过公开的状态词条互相咬合，玩家自己发现「原来能飞就炸不到」比卡面上写十行说明有效得多。后续卡牌应当继续往这一层加，而不是继续堆纯数值。

三条贯穿全文的规则：

- **效果可叠加，且互相独立计算持续时长。** 每次选牌产生的是独立的效果实例，同类效果不合并、不刷新时长、不互斥。玩家手上同时挂着三条各自倒计时的增益是常态。
- **全部时长以模拟时间计**，随选牌慢放同步减速。唯一按现实时间计的是选牌的 20 秒限时（[玩法设计 §4](game-design.md)）。
- **规则与表现单向依赖。** 装备的图、拖尾的粒子、交换时的镜头移动都不进入 tick 计算；美术资源缺失时规则照常运行，只是画面上什么都没有。

## 2. 与规则内核的边界

三条边界决定了卡牌能做什么、不能做什么。它们在[玩法设计](game-design.md)定义，这里只说清楚每条为什么长成这样——照着抄容易，改错也容易。

### 2.1 跨马交互是双向的

玩家的卡可以炸停一匹电脑马、和它交换位置、用重力井拖慢它；反过来，电脑马抽到的卡同样可以作用于玩家。唯一禁死的是**性格参数**：任何卡都不得写 `base/min/max/gain/slack/ease/amp/tau`，也不得进入电脑马目标速度函数的入参。

**双向意味着反馈回路是闭合的，代价要说清楚。** 电脑马读玩家位置来决定速度，而它的卡又能改玩家速度，两个方向都通。这个闭环承受得住，因为橡皮筋本身是负反馈控制器——它追的是身位差，外力把玩家拖慢只会让它少发力，不会越振越大，这个时候马的阻尼参数就非常重要了，允许马更晚减少发力、或者使减少发力这个进度变得更慢。

性格参数之所以单独禁死，正是因为它们是标定的锚点。炸弹、交换、重力井、天气都只改瞬时量，扰动的是收敛过程而不是分类；性格参数一旦可写，连定性分类都不剩了。

### 2.2 里程与位置是两个量

检查点按每匹马自身跑过的里程触发，位置跳变不产生里程（[玩法设计 §3](game-design.md)）。对卡牌设计来说，这条带来两个必须记住的后果：

- **传送类卡牌不需要任何特殊规则。** 来回交换刷不出第四次抽卡，被换到后面也不会重复触发已消费的档位。
- **提前冲线的马拿不满三次抽卡。** 把自己换到终点前，就是用一次抽卡机会换一段捷径。这个取舍必须写进卡面描述，不能让玩家事后才发现。

### 2.3 负面效果的下界

负面效果不得使速度永久为零，也不得使任何一匹马无法完赛。**瞬时归零后立即重新起步是允许的**——【死亡】正是如此，比赛仍然继续，只是慢了一两秒。

## 3. 效果原语

一切卡牌效果由九类原语组合而成。新增卡牌若需要第十类原语，是架构信号，先改[效果系统架构](architecture/effect-system.md)再加卡。

| 原语 | 含义 | 是否有视觉资源需求 | 本文实例 |
| --- | --- | --- | --- |
| `Modifier` | 对速度、体力等连续量的乘区贡献 | 否（通常由携带它的装备/状态表现） | 各类「加速 X%」、体力消耗减半 |
| `Status` | 布尔或层数标记，可被其他原语查询 | 是（附加在马身上的视觉态） | 【起飞】【运气E】【火焰】【重生】 |
| `Equipment` | 挂到骨架插槽的限时对象，携带若干 `Modifier`/`Status`/`Ability` | 是（必须有图与动画） | 【火箭喷射器】【史瓦西黑洞】【风火轮】 |
| `Ability` | 覆盖或扩展玩家输入绑定 | 是（按钮形态变化） | 【拍手交换】、风火轮的长按 |
| `Hazard` | 放置在赛道坐标上的独立实体，被马匹触碰时结算 | 是（赛道上的物件 + 触发动画） | 炸弹 |
| `Field` | 以某匹马为中心、按距离作用于其他马的区域效果 | 是（范围与受影响目标的提示） | 重力井 |
| `DrawRule` | 修改牌堆游标的取牌行为 | 是（选牌面板的形态变化） | 【刷新】、自动抽取、断卡 |
| `Environment` | 比赛级的全局状态，**单槽**，新的完整替换旧的 | 是（全场天气表现） | 【起风了】的风向 |
| `Trigger` | 挂一个条件与一段结算，条件满足时触发一次 | 否（由被触发的效果表现） | 运气E 到期死亡、火焰 7 层死亡 |

### 3.1 效果实例与独立计时

每次选牌生成一个或多个 `EffectInstance`：

```ts
interface EffectInstance {
  instanceId: number        // 本场自增，决定同 tick 内的处理顺序
  sourceCardId: string
  primitive: PrimitiveKind
  appliedAtTick: number
  durationTicks: number | null   // null = 持续到比赛结束
  payload: unknown          // 该原语的参数
}
```

默认叠加策略是 `independent`：不查重、不合并、不刷新时长。两张都给加速的卡同时在手，就是两条各自倒计时的实例，到期各走各的。

但「独立」不是唯一策略——有些效果占用的是**唯一资源**（一个 gogo 按钮、一个插槽、一片天空），它们必须显式声明别的策略。四种策略覆盖当前全部情形：

| 策略 | 语义 | 用在哪 |
| --- | --- | --- |
| `independent` | 各自计时、各自生效，互不干扰 | 默认；全部纯增益 |
| `replace` | 单槽，新的完整顶掉旧的，旧的立即失效 | `Ability` 绑定（§6）、`Equipment` 同插槽（§5）、`Environment` 全局槽（§7.4） |
| `refresh` | 再次获得同一效果时重置剩余时长，不新增实例 | 【顺手牵羊】转移过来的装备 |
| `stackable` | 累加层数，层数本身是状态 | 【火焰】 |

**`replace` 是有损的**：被顶掉的实例直接消失，不是暂停也不是排队。先拿的拍手交换被后拿的风火轮顶掉，那 30 秒就没了。

### 3.2 数值结算：三种算子与固定阶段

| 算子 | 记法 | 结算 | 数值性格 |
| --- | --- | --- | --- |
| 直接加算 `add` | `+k`（速度单位） | 池内累加，最先应用 | 低速时最强、高速时被稀释；适合落后补偿与起步类 |
| 百分比加算 `padd` | `+p%` | 池内累加后一次性乘上 | 随基础速度等比放大；**边际递减**，堆得越多单张越不值钱 |
| 直接乘算 `mul` | `×k` | 逐实例连乘 | **边际递增**，堆得越多单张越值钱 |

**流水线算的是速度带，不是速度本身。** 玩家马的速度由加速度积分出来，落在 `[vLow, vHigh]` 这条带里（[玩法设计 §5](game-design.md)）；卡牌改的是带的位置，手决定贴带子多近。同一条流水线跑两遍，分别作用于 `vLowBase` 与 `vHighBase`：

```
阶段 A   + Σ add                                  直接加算池
阶段 B   × (1 + B1 + clamp(B3, -0.6, +0.6))       百分比加算，两个子池
阶段 C   × Π mul_j                                逐实例连乘
阶段 D   clamp(硬上下限)
```

**同一阶段内的实例可交换，因此拿牌顺序不影响结果。**

B1 卡牌增益与 B3 外部场（重力井、天气）同在阶段 B，因此彼此之间也是加法；分成两个子池只为各自能单独钳制。**节奏不在这里**——它驱动的是加速度，不是速度带。

外部场压低速度带时，`clamp` 会在同一 tick 把超出新上界的速度直接拽下来——**这就是重力井那种「突然被拽住」的手感，不需要额外机制**。电脑马那一侧走的是另一条路（作用于目标速度、绕过阻尼，见[玩法设计 §7](game-design.md)），两条路给出的体感一致。

【死亡】不在这条流水线里：它归零的是速度本身而不是速度带，并且会临时解除 `vLow` 下界，否则 `clamp` 会在下一帧就把速度弹回去（[玩法设计 §5](game-design.md)）。

**阶段 C 是唯一会爆炸的地方，必须当稀缺资源管理。** 五张 `padd` 是 `1 + 0.2×5 = 2.0`，五张 `mul` 是 `1.2⁵ = 2.49`，而且每多一张涨幅更大。设计规则：卡池里带 `mul` 的卡数量受控，且不应存在两张纯 `mul` 增益卡能同时生效的组合；`mul` 的正确用法是**负向**（减速、惩罚）与一次性大额收益，不是常规加速。

修正不止作用于速度。`target` 决定它落在哪个量上，这样「改上限」「改加速度」「改体力」都不需要新原语：

| `target` | 含义 |
| --- | --- |
| `speed` | 整条速度带，`vLow` 与 `vHigh` 同比缩放（默认；「加速 X%」都是它） |
| `speedMax` | 只动 `vHigh`——焊死或抬高天花板（【永动机】） |
| `speedMin` | 只动 `vLow`——改变松手后滑回的位置 |
| `accel` | 动 `aMax` 与 `aIdle`，改的是「多快够得着天花板」 |
| `staminaCost` / `staminaRegen` | 体力消耗与恢复，沿用同一套阶段 |

`gate` 决定这条修正何时生效，不满足时该实例不进入任何阶段。状态门控（「只对【起飞】的马生效」）与资源门控（「体力低于 30% 时」）共用这一个字段：

```ts
interface ModifierDecl {
  target: ModifierTarget
  op: 'add' | 'padd' | 'mul'
  pool?: 'card' | 'rhythm' | 'field'   // 仅 padd 需要
  value: Fixed
  gate?: { status: StatusId } | { resource: ResourceId; below?: Fixed; above?: Fixed }
}
```

**构筑深度来自元卡的时机，不来自算术顺序。** 「选择困难综合症」放大后续所有卡、「海贼王的宝藏」把刷新游标推向牌底强卡、「最后的波纹」直接砍掉后续——这三张的价值随检查点严格递减。而【顺手牵羊】正相反，它的价值随检查点递增（§8.2 C-13）。一副牌里同时存在这两种斜率，才有真正的取舍。

### 3.3 机制覆盖清单

这张表的用途是**在写代码之前就知道哪一类卡会逼着重构**。加卡前先在这里找对应行：有 ✅ 的照着填数据，没有的先改架构。

「瞬时动作」不单列为原语：放炸弹、转移装备、交换位置、回满体力都是效果实例挂载那一刻的一次写入，任何原语都能在 `onEffectApply` 里做，不需要新东西。

| 机制 | 状态 | 承载 | 代表卡 |
| --- | --- | --- | --- |
| 自身数值修正，三种算子 | ✅ | `Modifier.op` | 全部加速卡、薄肌系列（`add`） |
| 修正非速度量（上限、加速度、体力） | ✅ | `Modifier.target` | C-02 / C-14 / C-15 |
| 条件生效（状态门控） | ✅ | `Modifier.gate` | 起风了 |
| 布尔状态与层数状态 | ✅ | `Status` | 起飞、火焰 |
| 装备、插槽、挂点 | ✅ | `Equipment` | 四件装备 |
| 输入绑定覆盖 | ✅ | `Ability` | 不义游戏、风火轮 |
| 赛道实体 | ✅ | `Hazard` | 炸弹来咯 |
| 区域场 | ✅ | `Field` | 重力井 |
| 全局环境、单槽替换 | ✅ | `Environment` | 起风了 |
| 跨马状态转移 | ✅ | `Equipment` 转移 | 顺手牵羊 |
| 条件触发（到期、层数、资源） | ✅ | `Trigger` | C-02、C-11、C-16 |
| 发牌规则修正 | ✅ | `DrawRule` | 三张元卡 |
| 一次性资源写入 | ✅ | `onEffectApply` 瞬时动作 | 肾上腺素 |
| 资源越过上限 | ✅ | 体力模型的 overcap 分支 | 肾上腺素 |
| 纯外观状态 | ✅ | 零 `Modifier` 的 `Status` | 黄毛、染成绿的 |
| 表现层剥夺 | ✅ | 渲染层读取的 `Status` | 理解孙学 |
| 组合 / 套牌判定 | ✅ | `Trigger` 的 `setMatch` 条件 | 版本答案（§7.6） |
| 强制改写名次 | ✅ | 骨架 `forcedRank` | 版本答案（§7.6） |
| **核心规则抑制** | ⚠️ | 需要 tags + 移除 API | 咖啡因过量 |
| **通用效果移除 / 驱散** | ⚠️ | 只有装备可被移除 | —— |
| **替换型反应** | ❌ | —— | —— |
| **自身位移** | ⚠️ | 只有【交换】一种形态 | 不义游戏 |

三个缺口的代价不一样，建议区别对待：

- **通用效果移除（现在必须补，已经有卡在等它）。** 【咖啡因过量】要关掉力竭惩罚，这是第三张需要它的卡：干净的做法是把力竭惩罚本身实现成一个系统自持的效果实例（`tags: ['system','debuff']`），抑制它就是按 tag 移除，而不是在体力模块里插一个 `if (!亢奋)` 的特判。给 `EffectInstance` 加 `tags: ('buff'|'debuff'|'equipment'|'env'|'system')[]` 再开一个按 tag 查询并移除的 API，成本是两个字段；等到第四张卡再补，就是把十几处挂载点连同散落各处的特判一起改。**每多一张「关掉某条规则」的卡而不补这个 API，骨架里就多一个写死的布尔分支**，那正是第 1 节说的「谁都不敢改的函数」的长法。
- **替换型反应（建议先不补）。** 「下次受到【死亡】时改为免疫」这类需要在效果结算**之前**截断，是一个拦截链而不是触发器，与现在「先算完再通知」的顺序相反。它值一次单独的架构讨论，不该顺手塞进来。
- **自身位移（等有卡再说）。** 【交换】已经跑通了位置跳变与里程的关系（§2.2），真要加「瞬移 / 后退 / 拉近」，复用同一条 `onPositionJump` 通路即可，不构成重构。

## 4. 状态词条

状态是可被其他效果查询的标记，是卡牌之间产生化学反应的接口（§1）。带 † 的条目是本文补充的建议默认，非用户原始要求。

### 【起飞】Airborne

马悬浮于赛道半个马身高度。

- 本身不改变速度；速度增益由携带它的卡另行给出。
- **免疫全部 `Hazard`**：悬空的马不触发地面炸弹。这是构筑交互层的第一条正式规则，不是特例。
- 视觉：马整体 y 偏移，地面投影缩小并偏移；全部挂载装备跟随偏移。

### 【死亡】Death

- 当前速度立即归零，**位置不变，不退回原点**。
- **恢复期间速度带的下界 `vLow` 暂时解除**，直到速度爬回 `vLow`。没有这条，`clamp` 会在下一帧把速度弹回 `vLow`，死亡就没有代价了。
- 恢复加速度不低于 `aMax / 2`，与玩家此刻点不点无关——这是比赛能终止的保证（[玩法设计 §5](game-design.md)）。在【力竭】状态下死亡是最坏情况：不能 gogo，只能靠这条保底爬回去。
- 获得 5 秒【重生】状态。
- † 不清除任何已有的效果实例、装备或状态；死亡只打断速度，不打断构筑。
- 不影响里程：里程只累计自身位移，速度为零的那段自然不产生里程，抽卡机会因此被推迟而不是被取消。

### 【重生】Respawning

- 持续 5 秒，视觉为消失/出现的闪烁。
- † 期间免疫再次【死亡】。没有这条，多枚炸弹会连锁把一匹马按在原地，那既不好笑也不可控。

### 【运气E】Luck E

- 厄运标记。持续期间，任何随机判定对该马取最差结果（当前卡池尚无此类判定，字段为后续卡预留）。
- **到期时必定结算一次【死亡】。** 这是「旋转突进的蓝色小马」承诺的代价，不是概率事件。

### 【火焰】Burning（层数状态）

- 层数上限 7。达到 7 层立即结算一次【死亡】，并清空层数，† 随后层数清零，装备本身不消失、不重置其 30 秒计时。
- 获得速率与由携带它的效果定义（目前只有风火轮：长按每秒 +1），衰减速度始终为：停止获得 3 秒后每秒 −1。
- 视觉：层数需要在马身上可读，7 层的逼近感是这张卡的全部紧张来源。

### 【亢奋】Wired

- 体力消耗到 0 后不再继续消耗，体力停在 0，不产生负值或欠债。
- **【力竭】整个状态被抑制**：速度不被压到 `vLow`，gogo 按钮也不锁死，因此不存在「恢复到 30% 才解除」那道回滞（[玩法设计 §5](game-design.md)）。
- 持续期间节奏点击没有体力代价，这是【咖啡因过量】唯一要表达的事。
- 视觉：体力条空了但在发光，马眼变成漩涡。

### 【毛色】Coat（外观状态）

- 携带一个颜色值，**没有任何数值效果**。
- 它存在的理由有两个：让玩家把马改成自己想要的样子，以及作为组合判定的输入（§7.6）。纯外观状态因此不是「没有效果的状态」，它是可被查询的标记。
- 同时只有一个毛色生效（`replace`，§3.1）：后染的盖掉先染的。
- 视觉：马匹主体贴图换色，装备与拖尾不跟着变。

### 【视野剥夺】Blinded

- 其他马的精灵、装备与拖尾**全部不渲染**。
- **只作用于渲染，不作用于规则**：其他马照常跑、照常放炸弹、照常和你交换位置。
- † HUD 名次条保留，方向箭头保留；否则玩家会彻底失去方向感（更极端的版本见 §10）。
- 视觉：其他赛道空着，只剩赛道线与场景。

### 【目中无人】Blinded——pro

- **只作用于渲染，也作用于规则**：其他马照常跑、照常放炸弹，但不会和你交换位置，炸弹也不会炸到你，其他马引发的全场天气效果，也不会影响到你。
- 其他表现与Blinded一致

### 【拍手交换 CD】SwapCooldown

- 2 秒内置冷却，期间 gogo 按钮不响应交换。
- 视觉：按钮上的冷却圈。

## 5. 装备词条

装备是挂到骨架插槽的持久对象，**每一件都必须有图与动画**，资源清单见 §9。

| 装备 | 插槽 | 携带的效果 | 时长 |
| --- | --- | --- | --- |
| 【火箭喷射器】 | `torso` | 体力消耗减半（C2 区）、加速 15%（B1 区） | 40s |
| 【史瓦西黑洞】 | `torso` | `Field`：重力井 | 10s |
| 【风火轮】 | `hoof_fl` `hoof_fr` `hoof_bl` `hoof_br`（四件同时） | `Ability`：长按加速、【起飞】、【火焰】累积 | 30s |
| 【彩虹拖尾】 | `tail` | 加速 10%（B1 区） | 60s |

装备到期时播卸载动画，† 卸载动画不阻塞效果失效——效果在到期那一 tick 就停，动画只是追着演。
同一插槽同时只能装一件装备，新的覆盖旧的。覆盖时，旧的先完整执行卸载，再添加新的。

## 6. 能力与输入绑定

「gogo」按钮的默认行为是快跑节奏点击（[玩法设计 §5](game-design.md)）。`Ability` 以单槽替换的方式覆盖它：同时只有一个绑定生效，后获得的直接顶掉先获得的（`replace`，§3.1）。

| 能力 | 交互 | 行为 |
| --- | --- | --- |
| 默认 | 点击 | 频率驱动加速度，速度爬向 `vHigh` |
| 【拍手交换】 | 点击 | 与相邻 `laneIndex` 的未冲线马随机交换，2 秒 CD |
| 【风火轮】 | 长按 | 按住时【起飞】+ 加速 40% + 每秒 1 层【火焰】；松开即失去全部三项 |

**gogo 被占用期间，等效频率锁定为 `f̂ = 0.5`**，加速度与体力收支都按这个频率算，不做实时判定、也不归零。归零会让屏幕上唯一的持续反馈突然消失；锁在一半则保留了明确的机会成本：**打得好的玩家在占用期间是净亏的，打得差的是净赚的**。定义见[玩法设计 §5](game-design.md)。

因此风火轮的净收益是 `+40% − (maxRhythm − maxRhythm/2)`，不是 +40%。**这一点无须写进卡面描述**，只增加复杂的理解成本。

† 覆盖规则：后获得的覆盖先获得的，先获得的效果则消失，都到期则回到默认行为。

### 6.1 【交换】的完整定义

`horseId` 是身份，`laneIndex` 是可变的上下站位（[玩法设计 §2](game-design.md)）。因此【交换】在规则层交换两匹马的 **`pos` 与 `laneIndex`**；里程 `dist`、速度和冲线兜底排序保持不变，画面按新的 `laneIndex` 渲染。

- 目标是**相邻 `laneIndex`** 中随机一匹未冲线马。随机源为 `H(seed, "swap", swapIndex)`，`swapIndex` 本场自增，因此可复算。
- 玩家在最外侧 `laneIndex` 时只有一个相邻位置，不做随机。
- 双方交换 `pos` 与 `laneIndex`，**各自速度不变**，**里程各自保留**，不出现过渡动画。
- 镜头通过快速平滑移动跟随玩家马，† 镜头动画不进 tick，掉帧或关闭动画不改变结果。
- † 已冲线的马不作为交换目标。
- 交换目标只从相邻 `laneIndex` 的未冲线马中取，因此最多把玩家换到一匹领先马的位置，不直接制造冲线；代价是里程不足，很可能少拿一次抽卡（§2.3）。

**这张卡是双向赌博**：相邻的马可能在前面，也可能在后面。随机而非选择，是它成立的前提——能选目标就变成了单纯的位移道具，梗也没了。

## 7. 场上实体、区域场与发牌修正

### 7.1 炸弹（Hazard）

「炸弹来咯」的效果：**给其他四条`laneIndex`赛道各放置一枚炸弹，位置是放置瞬间触发卡牌的 `pos`。**

- 马匹位置跨过自己那枚炸弹的 `pos` 时触发，结算一次【死亡】，炸弹消失。
- 【起飞】状态的马不触发（§4）。
- 炸弹是中立对象，可以炸到触发者（通过【交换】切换了赛道），触发这张卡牌效果的也可以是电脑马。
- † 炸弹永久留在赛道上直到被触发或比赛结束，无寿命。
- 判定用位移区间而非坐标相等：高速下按坐标相等会漏判（见[效果系统架构 §5](architecture/effect-system.md)）。
- 视觉：赛道上的炸弹、引信循环动画、爆炸动画。

### 7.2 重力井（Field）

装备【史瓦西黑洞】在躯干，持续 10 秒：

- **前方**的马受到减速，**后方**的马受到加速，两者都按距离衰减，最高 60%。
- † 衰减为线性：`k = 0.6 × max(0, 1 − d / R)`，`d` 为沿赛道的绝对距离，`R` 为作用半径。
- 作用于全部其他未冲线的马，贡献进它们的 B3 区。

**重力井作用在电脑马的阻尼输出之后，绕过 `tau`，也绕过 `min_i` / `max_i`。** 这与 `card_i` 相反，是刻意的：`tau` 阻尼存在的理由是把电脑马自己吃卡的阶跃摊成「渐渐提上来」（[玩法设计 §7](game-design.md)），而重力井要的正是**突然被拽住**的戏剧性；若同样走阻尼，10 秒的效果会被摊到几乎看不见。绕过 `min_i` 同理——一匹 `min_i` 高的马不应当因为性格参数而免疫黑洞。代价是必须在最外层补一道全局 clamp 兜住速度，见[效果系统架构 §5](architecture/effect-system.md)。

**后方加速是这张卡的真实代价，不是副作用。** 它把身后的追兵拉近，换取把身前的对手按住 10 秒。

### 7.3 发牌修正（DrawRule）

发牌是一副 14 张有序牌堆加一个游标（[玩法设计 §4](game-design.md)），因此发牌修正全部是对**游标**的操作，不是对概率的操作：

| 修正 | 来源 | 定义 |
| --- | --- | --- |
| 【刷新】 | 海贼王的宝藏 | 展示的三张卡牌下方都出现可点击的刷新按钮，被刷新的卡牌由 `deck[cursor]` 顶替，游标前进 1，另外两张不动。† 刷新不重置 20 秒限时；† 刷新额度可累计并在任意后续检查点使用；† 游标到达牌堆末尾后按钮置灰；† 刷新后刷新按钮消失 |
| 自动抽取 | 选择困难综合症 | 后续检查点不展示面板，由 `H(seed, "autopick", cp)` 从展示的三张中直接选定一张。† 自动抽取仍触发慢放与卡面展示动画，但不接受输入——玩家要看到自己被剥夺了选择权，这才是梗。† 剥夺的是选择权也包括刷新权 |
| 效果加成 | 选择困难综合症 | 后续获得的每张卡**额外附带 +20% 加速**（B1 区），持续时间跟随该卡自身主效果时长；† 瞬时卡按 20 秒计 |
| 断卡 | 最后的波纹 | 后续检查点不再展示卡牌，† 游标停在原地不再前进。结算记录中该次选择记为 `null` 且原因为 `forfeited`，与超时的 `null` 区分 |

**「海贼王的宝藏」在牌堆模型下只需要一个效果，不需要两个。** 它原本的设计是「更可能出现高品质 + 刷新一次」，但最后两张牌默认的就是强卡，这里的刷新选中的就是从牌底开始计数的卡。【刷新】使用一个独立的游标，是从牌底向前的操作，和游标是正相反的。

**「最后的波纹」在第三个检查点拿到时没有代价，这是玩法而不是漏洞。** 识别出「最后一个路口可以白嫖 40%」本身就是构筑理解的一部分，不加可用性限制、不做特判。

### 7.4 环境（Environment）

环境是**比赛级的全局状态，只有一个槽位**。它不挂在任何一匹马身上，作用对象由它自己声明；新的环境效果完整替换旧的，旧的立即失效（`replace` 策略，§3.1）。

【起风了】是第一张环境卡：

- 随机选一个风向，随机源 `H(seed, "wind", windIndex)`，`windIndex` 本场自增。
- **只作用于全场处于【起飞】状态的马**，玩家与电脑马一视同仁——这是 `gate: { status: 'airborne' }` 的第一个实例。
- 逆风（终点吹向起点）速度 −10%，顺风（起点吹向终点）+10%，贡献进 B3 外部场池。
- **持续时间无限**，直到比赛结束或被下一个环境效果覆盖。

环境槽是单槽而不是多层叠加，理由不是省事：天气是玩家一眼要能读懂的全局信息，两层风同时吹没有任何视觉表达方式。单槽同时也给了后续环境卡一个天然的互动点——用一张新天气盖掉对自己不利的旧天气，本身就是一步棋。

**这是第一张棋盘状态卡，不是自增益卡。** 它可能对自己是负的、对对手是正的；方向随机，所以拿它就是赌。它也是第一张**必须配合别的卡才有意义**的牌：没有任何起飞手段时它完全空转。这两点让它在卡池里承担的角色与其他卡都不同——先有【中国马能飞】或【风火轮】，它才是一张牌。

### 7.5 跨马状态转移

【顺手牵羊】要把一件装备从别人身上摘下来装到自己身上，这是第一个**转移**而非施加的效果，它对架构提出两条新要求：

- **电脑马必须持有真实的 `Equipment` 实例**，不能只是视觉图层。否则场上无物可偷。
- **装备可以被移除**，移除时它携带的全部 `Modifier` / `Status` / `Ability` 一并失效，原持有者的 `card_i` 贡献同步下降。

转移规则：

- 从「全部其他未冲线的马身上的全部装备实例」里等概率取一件，随机源 `H(seed, "steal", stealIndex)`。
- 装到自己身上，**时长刷新为该装备的完整时长**（`refresh` 策略，§3.1）。
- 若与自己已有装备同插槽，按 §5 的插槽规则新的覆盖旧的。
- **场上没有任何装备时，这张牌没有效果**，也不返还、不补抽。

**空过是设计的一部分，不是待修的缺陷。** 第一个检查点场上通常一件装备都没有，这张牌那时是废纸；到第三个检查点，四匹电脑马身上多半挂着东西，它就是全场最强的一张。**它的价值随检查点递增，与三张元卡正好相反**——一副牌里同时存在两种斜率，玩家才需要真的判断「现在是不是拿它的时候」。

### 7.6 组合彩蛋：版本答案

**同时持有【薄肌】或【薄肌 pro max ultra】、【黄毛】、【理解孙学】三张，触发彩蛋【版本答案】：玩家直接赢得比赛成为第一，无视已经冲线的小马。**

#### 判定与结算

- 判定发生在第三张构件生效的那一 tick（选牌即时生效，[玩法设计 §4](game-design.md)）。
- 触发瞬间**等同于玩家冲线**：封存输入、进入结算流程。
- 玩家名次强制为 1。**已经冲线的马整体下移一位**，未冲线的马按各自当前实际顺序占据 2–5 名。
- 全场唯一一次性彩蛋，不可重复触发。
- 电脑马不触发版本答案

#### 这条打破了一个核心不变量

[玩法设计 §3](game-design.md) 写着「名次是位置的副产品：谁先跨过 L 谁在前」，还写着「玩家冲线的瞬间，玩家自己的名次即已确定」。**版本答案是这两句话唯一的例外**，而且是刻意的例外，不是疏漏。代价必须记在明处：

- 规则骨架需要一个 `forcedRank` 字段，名次计算读它；这是骨架唯一一处「名次不由位置推出」的分支。
- 校验器语义受影响：将来任何 `IResultValidator` 若要验算名次，必须知道这条规则的存在，否则它会把一场合法的彩蛋局判成作弊。这一条要写进 `rulesVersion` 的说明。
- 链上不受影响：合约对名次只做 1–5 的范围检查（[链上文档 §1.2](chain-and-economy.md)），rank = 1 照常受理。

**离线复算不需要新字段。** 三次选牌已经在结算 calldata 里，组合判定是这三个选择的确定性函数，复算方按同一规则走一遍自然得到同样的名次。加一个「彩蛋已触发」的标志位只对调试有用，不对可验证性有用。

#### 为什么这个组合成立

三张构件单独看都是废牌或近似废牌：【黄毛】零增益、【理解孙学】用信息换一点速度、【薄肌】只有 +10。**玩家必须把三次选牌全部押在垃圾上，而且在押下前两次的时候根本不知道第三张会不会出现。** 押错就是整场作废——这个代价本身就是彩蛋的门票，不需要额外限制。

组合成立还有两个结构性门槛，都不做特判：

- 三张构件必须**落在不同检查点的展示里**。两张挤在同一个三选一里，这一局的组合当场作废——一个检查点只能拿一张。
- **【刷新】帮不上忙。** 刷新从牌底向前取（§7.3），而牌底两张是保底强效果卡，凑组合的垃圾牌不会在那里。

#### 实现上不需要新原语

组合判定是 `Trigger` 的一种条件（持有效果集合匹配），不是第十类原语：

```ts
{ kind: 'setMatch',
  all: ['cosmetic.yellow_hair', 'cosmetic.sun_studies'],
  anyOf: [['buff.thin_muscle', 'buff.thin_muscle_pro']] }
```

这也是把 `Trigger` 显式化的第三个理由（前两个是运气E 到期、火焰 7 层，§3.3）：三处特例合成一处机制，再加彩蛋就是加一条数据。

### 7.7 卡池下限

[玩法设计 §6](game-design.md) 的静态断言是：**总卡池 ≥ 14 张，其中强效果子集 ≥ 2 张。** 品质在牌堆模型里不参与抽取，只是卡面表现与数值档位。

**建议把强效果子集直接定义为 `rare` 品质的卡集合**，不引入第三个维度。玩家在图鉴里看到的金框卡，就是牌堆末两张保底会给的卡，两个概念指同一件事；拆成两套标记迟早会出现「金框但不保底」的卡，那是纯粹的认知负担。

当前 Demo 卡池定案为 21 张（C-01 至 C-21），rare 12 张，两条断言都满足；不在 Demo 范围内的候选卡不进入本版卡池。

卡池从 14 涨到 21，一个连带效果要注意：**牌堆仍然只有 14 张，因此每一场都有 7 张卡根本不出现**。这对【版本答案】这类需要凑齐三张特定卡的组合影响最大——构件进不了牌堆，这一局就没有彩蛋。卡池越大，彩蛋越稀有，触发率必须在卡池定稿后重测（§7.6）。

## 8. 卡牌清单

### 8.1 卡牌数据结构

```ts
interface CardDef {
  cardId: string
  quality: 'common' | 'rare'       // rare 即强效果子集，参与牌堆末两张保底
  name: { zh: string; en: string }
  desc: { zh: string; en: string }  // 必须写明代价，尤其是 gogo 占用期间的节奏折损
  meme: string                      // 梗源，用于卡面美术方向与图鉴
  art: { icon: string; frame: string }
  cpuUsable: boolean                // 电脑马私有牌堆是否允许取到；所有卡必须显式声明
  effects: EffectDecl[]             // 该卡展开的效果原语声明
  stack?: StackPolicy               // 缺省 independent，见 §3.1
  modules: string[]                 // 该卡依赖的模块 id，用于静态检查缺模块
}
```

牌堆是对整副卡池的一次无放回定序，**没有「这张卡只在第几个检查点出现」这种字段**——牌堆在开局就已定序，无从知道某张牌会落在哪个检查点。

`modules` 字段的作用是让「加一张卡」在缺少对应模块时**编译期失败而不是运行时静默无效**。

`cpuUsable` 必须显式填写。电脑马只从 `cpuUsable: true` 的卡中派生私有牌堆；发牌修正、玩家输入绑定和只对玩家界面有意义的卡标为 `false`，不以“抽到后空过”掩盖作用域错误。

## 9. 美术与资源需求

装备要挂在马的不同部位，这项需求直接决定渲染层的结构，不能等美术交付时再补。

### 9.1 骨架插槽

马匹 rig 定义一组稳定命名的插槽，规则内核不认识它们，只有渲染层使用：

| 插槽 | 位置 | 当前使用者 |
| --- | --- | --- |
| `torso` | 躯干中部 | 火箭喷射器、史瓦西黑洞 |
| `head` | 头部 | 预留 |
| `hoof_fl` `hoof_fr` `hoof_bl` `hoof_br` | 四蹄 | 风火轮（四件） |
| `tail` | 尾根 | 彩虹拖尾发射点 |
| `body_center` | 身体中心 | 旋转突进的旋转轴心 |
| `orbit_up` `orbit_down` `orbit_front` | 相对 `body_center` 的轨道锚点 | 旋转突进的三个拖影点 |
| `aura` | 整体包围 | 重生闪烁、全身光效 |

插槽随马匹奔跑动画的关键帧移动。**【起飞】的 y 偏移作用于 rig 根节点**，全部挂载物自动跟随，不需要逐件处理。

### 9.2 每件装备的资源清单

一件装备的资源不止一张图：

| 资源 | 说明 | 缺失时的降级 |
| --- | --- | --- |
| 静态图 | 挂载态基础帧 | 占位色块 |
| 循环动画 | 挂载期间的 idle 循环（喷焰、吸积盘、火轮旋转） | 退化为静态图 |
| 装卸动画 | attach-in / detach-out | 直接出现/消失 |
| 渲染层级 | `behind_horse` / `on_horse` / `front_horse` | 默认 `on_horse` |
| 朝向处理 | 是否随马匹朝向翻转 | 默认翻转 |
| 卡面图标 | 选牌、HUD 生效槽、结算回顾三处共用（[架构 §9](architecture/overall.md)） | 占位图标 |

**资源缺失一律降级，不得阻断规则。** 规则内核不 import 任何资源清单；渲染层查不到资源就画占位，比赛照跑。这是把美术进度与玩法调参解耦的唯一方式——否则数值调不了，因为图还没画。

状态表现必须提供两类通用动效：状态实例首次挂载时，状态图标/徽章缩放并摇晃；已有状态增加层数时，状态图标/层数徽章再次缩放并摇晃。动效只由状态快照的新增或层数差异触发，不得按每个 tick 重复播放；资源缺失时保留同样的变换动效并使用占位图标。

### 9.3 拖尾类效果

彩虹拖尾与旋转突进的三个拖影点都需要历史位置队列。† 队列长度、采样率与渲染完全属于表现层，**不进 tick 计算、不进结算记录**。慢放期间拖尾按模拟时间采样，以免选牌时拖尾长度突变。

【交换】会让两匹马的 `laneIndex` 与渲染行瞬间互换，† 拖尾队列随之跟到新行，不做跨行插值——插值会画出一条横跨赛道的彩虹，那不是交换该有的读法。
